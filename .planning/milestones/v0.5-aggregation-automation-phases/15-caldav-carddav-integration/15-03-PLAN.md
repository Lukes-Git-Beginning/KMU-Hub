    Per CONTEXT.md locked decision: "Push notifications where clients support it, polling as fallback." This task implements the server-side WebDAV-Push mechanism so clients that support push (primarily macOS Calendar) receive change notifications instead of polling. Polling via RFC 6578 sync tokens (already implemented in 15-01) remains the fallback.

    **Migration 000051: Push subscriptions**

    Create `caldav_push_subscriptions` table:
    - `id UUID PRIMARY KEY DEFAULT uuid_generate_v4()`
    - `user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE`
    - `collection_type VARCHAR(20) NOT NULL` -- 'calendar', 'addressbook'
    - `collection_id UUID NOT NULL` -- which calendar or address book
    - `push_url TEXT NOT NULL` -- client-provided callback URL for push notifications
    - `push_topic TEXT` -- optional topic identifier (Apple push uses this)
    - `expires_at TIMESTAMPTZ NOT NULL` -- subscription expiry (clients must renew)
    - `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`
    - `updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`

    Indexes:
    - `idx_push_subs_collection ON caldav_push_subscriptions (collection_type, collection_id)`
    - `idx_push_subs_user ON caldav_push_subscriptions (user_id)`
    - `idx_push_subs_expiry ON caldav_push_subscriptions (expires_at)` -- for cleanup queries

    Down migration: DROP TABLE caldav_push_subscriptions.

    **Push subscription service** in `backend/internal/caldav/push_subscription.go`:

    ```go
    type PushSubscription struct {
        ID             uuid.UUID
        UserID         uuid.UUID
        CollectionType string
        CollectionID   uuid.UUID
        PushURL        string
        PushTopic      string
        ExpiresAt      time.Time
        CreatedAt      time.Time
        UpdatedAt      time.Time
    }

    type PushSubscriptionService struct {
        pool *pgxpool.Pool
    }

    func NewPushSubscriptionService(pool *pgxpool.Pool) *PushSubscriptionService
    ```

    Methods:
    - `Subscribe(ctx, userID, collectionType, collectionID, pushURL, pushTopic string, ttl time.Duration) (*PushSubscription, error)`: Upsert subscription (ON CONFLICT user_id, collection_type, collection_id, push_url DO UPDATE SET expires_at, updated_at). Default TTL: 7 days. Return subscription with expiry.
    - `Unsubscribe(ctx, userID, collectionType, collectionID, pushURL) error`: Delete matching subscription.
    - `GetSubscriptionsForCollection(ctx, collectionType, collectionID) ([]*PushSubscription, error)`: Return all active (non-expired) subscriptions for a collection. Filter WHERE expires_at > NOW().
    - `CleanupExpired(ctx) (int64, error)`: DELETE WHERE expires_at < NOW(). Return count deleted. Called periodically (e.g., every hour via goroutine or on each push notification batch).

    The subscription is registered when a CalDAV/CardDAV client sends a SUBSCRIBE or includes push headers in PROPFIND. In the gateway route_caldav.go (Task 1 of this plan), add handling for the `Push-Subscribe` header on PROPFIND responses: if the client sends a `Push-Transports: DAV` and `Push-Subscribe` header, extract the push URL and register via PushSubscriptionService. Return the `Push-Topic` header in PROPFIND responses for collections so clients know which topic to listen on.

    Specifically, add a wrapping middleware in route_caldav.go around the caldavHandler and carddavHandler that intercepts PROPFIND responses:
    - Check for `Push-Transports` header containing "DAV" on the request
    - If present, parse `Push-Subscribe` header for the callback URL
    - After the inner handler writes the response, call Subscribe to register/renew
    - Add `Push-Topic: {collection_id}` to the response headers

    **Push notifier** in `backend/internal/caldav/push_notifier.go`:

    ```go
    type PushNotifier struct {
        subscriptions *PushSubscriptionService
        httpClient    *http.Client
    }

    func NewPushNotifier(subscriptions *PushSubscriptionService) *PushNotifier
    ```

    Methods:
    - `NotifyCollectionChanged(ctx, collectionType, collectionID uuid.UUID) error`: Look up active subscriptions for the collection via GetSubscriptionsForCollection. For each subscription, send a minimal HTTP POST to the push_url with body containing the DAV:push-message (a simple XML body with the sync-token or just a "collection changed" signal). Fire-and-forget with a 5-second timeout per request. Log failures at warn level but do not fail the write operation. Use a goroutine pool (or single goroutine) to avoid blocking the CalDAV write path.
    - The POST body follows the WebDAV-Push draft format:
      ```xml
      <?xml version="1.0" encoding="utf-8"?>
      <push-message xmlns="DAV:">
        <topic>{push_topic}</topic>
      </push-message>
      ```
    - If the push_url returns 410 Gone, auto-unsubscribe (delete the subscription).
    - If the push_url returns 4xx/5xx, log and continue -- the client will fall back to polling.
