    **2. API Client** (`desktop/src/renderer/src/api/inbox-client.ts`):

    Create a fetch wrapper following the pattern from `calendar-client.ts` and `video-client.ts` (NOT openapi-fetch, since inbox is a new service without generated types).

    Base functions:
    - `inboxGet<T>(path: string, params?: Record<string, string>): Promise<T>` -- GET with query params
    - `inboxPost<T>(path: string, body?: unknown): Promise<T>` -- POST with JSON body
    - `inboxPut<T>(path: string, body: unknown): Promise<T>` -- PUT with JSON body
    - `inboxDelete(path: string): Promise<void>` -- DELETE

    All functions:
    - Use the auth store's token for Authorization header
    - Base URL: `/api/v1/inbox`
    - Throw on non-2xx responses with error message from response body
    - Include proper Content-Type headers

    Export typed API functions:
    - `listMessages(filter: InboxListFilter): Promise<InboxMessageList>`
    - `getMessage(id: string): Promise<InboxMessage>`
    - `markRead(id: string): Promise<void>`

    **3. TanStack Query Hooks** (`desktop/src/renderer/src/api/hooks/useInbox.ts`):

    Follow the pattern from `useFinance.ts` and `useHR.ts`.

    Query key factory:
    ```typescript
    const inboxKeys = {
      all: ['inbox'] as const,
      messages: (filter: InboxListFilter) => ['inbox', 'messages', filter] as const,
      message: (id: string) => ['inbox', 'message', id] as const,
      unread: () => ['inbox', 'unread'] as const,
      teams: () => ['inbox', 'teams'] as const,
      teamMembers: (teamId: string) => ['inbox', 'teams', teamId, 'members'] as const,
      rules: () => ['inbox', 'rules'] as const,
    };
    ```

    Queries:
    - `useInboxMessages(filter)` -- fetches messages with 30s staleTime for near-real-time
    - `useInboxMessage(id)` -- single message detail
    - `useUnreadCount()` -- unread counts with 15s staleTime (shown in sidebar badge)
    - `useTeamInboxes()` -- user's team inboxes
    - `useTeamMembers(teamId)` -- members of a team inbox
    - `useRoutingRules()` -- all routing rules

    Mutations with optimistic updates:
    - `useMarkRead()` -- optimistic: set is_read=true in cache, invalidate unread count
    - `useMarkUnread()` -- optimistic: set is_read=false
    - `useToggleStar()` -- optimistic: toggle is_starred
    - `useArchiveMessage()` -- optimistic: remove from list, invalidate messages
    - `useSnoozeMessage()` -- optimistic: remove from list (snoozed items hidden)
    - `useReplyToMessage()` -- invalidate message detail
    - `useAssignMessage()` -- optimistic: set assigned_to
    - `useClaimMessage()` -- optimistic: set assigned_to to current user
    - `useBulkMarkRead()` -- invalidate messages + unread count
    - `useBulkArchive()` -- invalidate messages
    - `useCreateTeamInbox()` -- invalidate teams
    - `useUpdateTeamInbox()` -- invalidate teams
    - `useDeleteTeamInbox()` -- invalidate teams
    - `useCreateRoutingRule()` -- invalidate rules
    - `useUpdateRoutingRule()` -- invalidate rules
    - `useDeleteRoutingRule()` -- invalidate rules
    - `useTestRoutingRule()` -- no cache (one-off mutation)

    All mutations show sonner toast on success/error (consistent with existing modules).
