  <action>
    Create three service packages following the established repository pattern.

    **CreditNote package (`internal/biz/creditnote/`):**

    Repository interface: Create, GetByID, List, SendCreditNote (assigns number), GetByInvoiceID.

    Service methods:
    - `Create(ctx, input) (*models.CreditNote, error)` -- validates original_invoice_id exists and is sent/paid/overdue (not draft/cancelled). Copies customer data from original invoice. Calculates tax. Input: OriginalInvoiceID, LineItems, TaxMode, Reason, UserID.
    - `GetByID(ctx, id) (*models.CreditNote, error)`
    - `List(ctx, filter) ([]*models.CreditNote, int, error)`
    - `Send(ctx, id, userID) error` -- draft->sent. Assigns credit note number via NextNumber (prefix "GS", e.g., GS-2026-0001) using the same sequence table with document_type='credit_note'.

    Errors: ErrCreditNoteNotFound, ErrCreditNoteNotDraft, ErrInvalidInvoiceForCredit.

    **Payment package (`internal/biz/payment/`):**

    Repository interface: Create, List (by invoice_id), Delete, SumByInvoiceID.

    Service methods:
    - `Record(ctx, input) (*models.Payment, error)` -- records payment. After recording, checks if sum of payments >= invoice gross_total. If so, calls invoice status transition to "paid". Input: InvoiceID, Amount (decimal), Date, Method, Reference, Notes, UserID.
    - `List(ctx, invoiceID) ([]*models.Payment, error)`
    - `Delete(ctx, id) error` -- only if invoice is not in a finalized state that prevents modification. After deletion, re-check if invoice should revert from paid to sent/overdue.

    **Dunning package (`internal/biz/dunning/`):**

    Repository interface: Create, GetByID, List (by invoice_id, by status), UpdateStatus, GetConfig, UpdateConfig, GetOverdueInvoicesForDunning.

    Service methods:
    - `GetConfig(ctx, tenantID) (*models.DunningConfig, error)` -- returns config or creates default (14/14/14 days intervals, 0/5/10 EUR fees per user decision: admin-configurable, no hardcoded defaults). If no config exists, create one with these defaults.
    - `UpdateConfig(ctx, tenantID, input) (*models.DunningConfig, error)` -- admin updates intervals and fees.
    - `DetectAndCreateDunnings(ctx, tenantID) ([]*models.DunningRecord, error)` -- semi-automatic per user decision: finds overdue invoices, checks existing dunning level, creates next-level draft dunning if interval elapsed. Logic:
      - Invoice overdue + no dunning yet + days_overdue >= level1_days -> create Level 1 draft
      - Invoice has Level 1 sent + days_since_level1_sent >= level2_days -> create Level 2 draft
      - Invoice has Level 2 sent + days_since_level2_sent >= level3_days -> create Level 3 draft
      - Never auto-creates if max level (3) already sent
    - `Send(ctx, id, userID) error` -- draft->sent, sets sent_at timestamp
    - `List(ctx, filter) ([]*models.DunningRecord, error)` -- filter by invoice_id, status, level
    - `CalculateInterest(ctx, invoiceGrossTotal decimal.Decimal, dueDate time.Time, basiszinssatz decimal.Decimal, isB2B bool) decimal.Decimal` -- Verzugszinsen per BGB section 288: B2C = basiszinssatz + 5%, B2B = basiszinssatz + 9%. Pro-rata daily calculation from due_date to today.

    Errors: ErrDunningNotFound, ErrDunningNotDraft, ErrDunningMaxLevel.

    All service constructors take: repository + any cross-service dependencies (e.g., payment.Service needs invoice repository for status check). Use interface injection, not concrete types.

    **Dashboard package (`internal/biz/dashboard/`):**

    Repository interface: GetDashboardMetrics (complex aggregation query).

    PostgresRepository: Single query (or 2-3 queries) that returns:
    - Revenue metrics: SUM of gross_total for invoices WHERE status IN ('sent','paid','overdue') (total_invoiced), SUM WHERE status='paid' (total_paid), SUM WHERE status IN ('sent','overdue') (total_outstanding), SUM WHERE status='overdue' (overdue_amount)
    - Pipeline metrics: COUNT of quotes WHERE status='sent' (quotes_pending), conversion rate (quotes accepted / quotes total), AVG invoice gross_total (average_deal_size)
    - Status breakdown: COUNT by invoice status (draft, sent, overdue, paid, cancelled)
    - Use date range filter (DateFrom, DateTo) from the request.
    - Also return: recent invoices (last 10), expiring quotes (valid_until within 7 days), pending dunnings (status=draft).

    Service: `GetDashboard(ctx, tenantID, dateFrom, dateTo) (*models.FinanceDashboard, error)` -- thin wrapper around repository, adds revenue forecast (simple: average monthly revenue * remaining months in year).

    **PDF Generator (`internal/biz/pdf/`):**

    Use maroto/v2 (github.com/johnfercher/maroto/v2). Install with `go get github.com/johnfercher/maroto/v2@latest`.

    `generator.go`:
    - `type Generator struct` with company settings for defaults.
    - `NewGenerator(settings models.CompanySettings) *Generator`
    - `GenerateQuotePDF(quote models.Quote) ([]byte, error)` -- returns PDF bytes
    - `GenerateInvoicePDF(invoice models.Invoice) ([]byte, error)` -- uses snapshot_data if available (sent invoice), otherwise live data (draft preview)
    - `GenerateCreditNotePDF(creditNote models.CreditNote) ([]byte, error)`
    - `GenerateDunningPDF(dunning models.DunningRecord, invoice models.Invoice, level int) ([]byte, error)`

    `templates.go` -- shared PDF layout functions:

    Per user decisions (clean minimal Stripe/Lexoffice aesthetic):
    - A4 portrait, 15mm margins
    - Header: company logo (left, loaded from URL or placeholder) + company details right-aligned (name, address, Handelsregister)
    - Recipient block: customer name + address (positioned per DIN 5008 window envelope standard if practical, otherwise top-left below header)
    - Document title: "Angebot" / "Rechnung" / "Gutschrift" / "Zahlungserinnerung" / "1. Mahnung" / "2. Mahnung" with document number and date
    - Line item table columns per user decision: Position | Bezeichnung | Menge | Einzelpreis | Gesamtpreis
    - Below table: Subtotal (Zwischensumme), per-rate tax lines (e.g., "MwSt 19%: 45.60 EUR", "MwSt 7%: 3.50 EUR"), Gesamtbetrag (bold)
    - For Reverse Charge: note "Steuerschuldnerschaft des Leistungsempfaengers (section 13b UStG)" below totals
    - For Kleinunternehmer: note "Kein Ausweis von Umsatzsteuer, da Kleinunternehmer gemaess section 19 UStG" below totals
    - Payment terms and notes section
    - Footer (every page): 3-column layout with Handelsregister | Steuernummer/USt-IdNr | Bank IBAN/BIC (Pflichtangaben per UStG section 14)
    - Accent color from company settings for horizontal rules and headings only
    - Font: Use maroto's built-in Helvetica (closest to sans-serif; custom font embedding is a stretch goal)
    - Thin 0.5pt borders on table, subtle row alternation if maroto supports it

    For dunning letters, tone varies by level per user decision:
    - Level 1 (Zahlungserinnerung): friendly, "wir moechten Sie hoeflich daran erinnern..."
    - Level 2 (1. Mahnung): formal, "trotz unserer Erinnerung..."
    - Level 3 (2. Mahnung / Letzte Mahnung): urgent, "sollte keine Zahlung erfolgen, sehen wir uns gezwungen, ein Inkassounternehmen zu beauftragen"
    - Include: Mahngebuehr (fee), Verzugszinsen (interest), Gesamtforderung (original + fee + interest)
