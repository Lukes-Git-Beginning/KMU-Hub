<task type="auto">
  <name>Task 1: Vault encryption service with AES-256-GCM and HKDF</name>
  <files>
    backend/internal/security/vault/crypto.go
    backend/internal/security/vault/service.go
    backend/internal/security/vault/repository.go
    backend/internal/security/vault/postgres_repository.go
  </files>
  <action>
    1. Create `crypto.go` with:
       - `DeriveKey(masterSecret []byte, context string) ([]byte, error)` using HKDF-SHA256 from `golang.org/x/crypto/hkdf`. Context string distinguishes key purpose (e.g., "vault-encryption", "totp-encryption"). Returns 32-byte key for AES-256.
       - `Encrypt(plaintext []byte, key []byte) (string, error)` using AES-256-GCM. Generates random nonce via crypto/rand, seals data, prepends nonce to ciphertext, returns base64-encoded string.
       - `Decrypt(encoded string, key []byte) ([]byte, error)` reverses Encrypt: base64 decode, split nonce, GCM open.
       - Package-level constants for key contexts: `KeyContextVault = "vault-encryption"`, `KeyContextTOTP = "totp-encryption"`.

    2. Create `repository.go` with Repository interface:
       - `GetByKeyName(ctx context.Context, keyName string) (*models.VaultSecret, error)`
       - `List(ctx context.Context) ([]*models.VaultSecret, error)`
       - `Create(ctx context.Context, secret *models.VaultSecret) error`
       - `Update(ctx context.Context, secret *models.VaultSecret) error`
       - `Delete(ctx context.Context, id uuid.UUID) error`

    3. Create `postgres_repository.go` implementing the Repository interface with pgx queries against vault_secrets table. List returns all secrets but with encrypted_value redacted (set to empty string) -- actual decryption happens in the service layer. Use standard pgx pool pattern matching existing repositories.

    4. Create `service.go` with:
       - `type Service struct { repo Repository; vaultKey []byte; totpKey []byte }`
       - `NewService(repo Repository, masterSecret string) (*Service, error)` -- derives vaultKey and totpKey from masterSecret using DeriveKey with different contexts. Returns error if masterSecret is empty or too short (min 32 chars).
       - `GetSecret(ctx context.Context, keyName string) (string, error)` -- gets encrypted value from repo, decrypts with vaultKey, returns plaintext.
       - `SetSecret(ctx context.Context, keyName, plaintext, description string, createdBy uuid.UUID) error` -- encrypts with vaultKey, stores via repo (create or update based on existence).
       - `ListSecrets(ctx context.Context) ([]*models.VaultSecret, error)` -- returns metadata only (no decrypted values).
       - `DeleteSecret(ctx context.Context, id uuid.UUID) error` -- deletes from repo.
       - `EncryptTOTPSecret(secret string) (string, error)` -- encrypts using totpKey (separate from vault key per research anti-pattern guidance).
       - `DecryptTOTPSecret(encrypted string) (string, error)` -- decrypts using totpKey.

    Use structured logging (slog) for all operations. Never log plaintext secrets or encryption keys.
  </action>
  <verify>
    - `cd backend && go build ./internal/security/vault/...` compiles
    - `cd backend && go vet ./internal/security/vault/...` passes
    - Verify crypto.go has both Encrypt and Decrypt functions
    - Verify service.go has separate vault and TOTP key derivation
  </verify>
  <done>Vault service encrypts/decrypts with AES-256-GCM, derives separate keys via HKDF, and stores encrypted secrets in PostgreSQL.</done>

       - `GetPolicy(ctx context.Context) (*models.PasswordPolicy, error)` -- returns current policy (there's only one row, return first or default)
       - `UpdatePolicy(ctx context.Context, policy *models.PasswordPolicy) error`
       - `AddPasswordHistory(ctx context.Context, userID uuid.UUID, passwordHash string) error`
       - `GetPasswordHistory(ctx context.Context, userID uuid.UUID, limit int) ([]string, error)` -- returns last N password hashes

    2. Create `postgres_repository.go` implementing Repository with pgx queries. GetPolicy returns a sensible default if no row exists (min_length=12, min_entropy=50.0, prevent_reuse_count=5, no complexity requirements per NIST recommendations).

    3. Create `policy.go` with:
       - `type Service struct { repo Repository }` + `NewService(repo Repository) *Service`
       - `ValidatePassword(ctx context.Context, password string) (bool, []string, error)` -- validates against current policy. Returns (valid, list of failure reasons, error). Uses `wagslane/go-password-validator` for entropy check (call `passwordvalidator.GetEntropy(password)` and compare against policy.MinEntropy). Also checks min length, and optional complexity requirements (uppercase, lowercase, digit, special) only if the policy has them enabled.
       - `CheckPasswordHistory(ctx context.Context, userID uuid.UUID, newPassword string) (bool, error)` -- hashes new password with bcrypt and compares against last N hashes from history. Returns true if password was NOT used before (i.e., it's safe to use). Note: bcrypt comparison requires checking each stored hash with bcrypt.CompareHashAndPassword since bcrypt salts differ.
       - `RecordPassword(ctx context.Context, userID uuid.UUID, passwordHash string) error` -- adds to password history.
       - `GetPolicy(ctx context.Context) (*models.PasswordPolicy, error)` -- returns current policy.
       - `UpdatePolicy(ctx context.Context, policy *models.PasswordPolicy, updatedBy uuid.UUID) error` -- updates policy.

    Failure reason strings should be human-readable (e.g., "Password must be at least 12 characters", "Password entropy too low (minimum 50 bits required)"). These will be translated by the frontend.
  </action>
