    1. Create `erasure.go`:
       - Define `ErasureHandler` interface:
         ```go
         type ErasureHandler interface {
             ModuleName() string
             PreviewErasure(ctx context.Context, userID uuid.UUID) (*models.ModuleErasurePreview, error)
             ExecuteErasure(ctx context.Context, userID uuid.UUID, anonymizedLabel string, action string) error
         }
         ```
         The `action` parameter is "anonymize" or "delete" (configurable per module by admin).

       - Implement handlers for each module:
         a. `AuthErasureHandler` -- preview: count user record + sessions + recovery codes. Execute: replace first_name with anonymizedLabel, last_name with empty, clear email (set to "deleted-{uuid}@deleted.local" to keep unique constraint), clear password hash, disable 2FA, delete recovery codes, delete sessions.
         b. `CRMErasureHandler` -- preview: count contacts/companies/deals/activities created by user. Execute: if "anonymize" replace creator names with anonymizedLabel; if "delete" remove records. Stub for now with placeholder counts.
         c. `ChatErasureHandler` -- preview: count messages by user. Execute: if "anonymize" replace sender display name in messages with anonymizedLabel (keep message content for thread context per user decision); if "delete" replace message content with "[Nachricht geloescht]". Stub for now.
         d. `WorkErasureHandler` -- preview: count tasks, comments, time entries. Execute: anonymize assignee/creator names. Stub for now.
         e. `CalendarErasureHandler` -- preview: count events, RSVPs. Execute: anonymize organizer/attendee. Stub for now.
         f. `NotificationErasureHandler` -- preview: count notifications. Execute: delete all user notifications. Stub for now.
         g. `AuditErasureHandler` -- NOTE: audit log entries are NEVER anonymized (they're compliance records). Preview returns 0 records. Execute is a no-op. The user_id in audit_log remains but maps to an anonymized user record.

    2. Create `service.go` with GDPR orchestration service:
       - `type Service struct { repo Repository; exportHandlers []DataExportHandler; erasureHandlers []ErasureHandler }`
       - `NewService(repo Repository) *Service` + `RegisterExportHandler(h DataExportHandler)` + `RegisterErasureHandler(h ErasureHandler)`

       Export methods:
       - `RequestExport(ctx context.Context, userID uuid.UUID) (*models.GDPRExportRequest, error)` -- creates request with status "pending", generates UUID.
       - `ListExports(ctx context.Context, userID *uuid.UUID, status string) ([]*models.GDPRExportRequest, error)` -- delegates to repo.
       - `ApproveExport(ctx context.Context, requestID uuid.UUID, reviewerID uuid.UUID) error` -- sets status to "approved", sets reviewed_by and reviewed_at. Then kicks off async export: go func that calls ExecuteExportAsync.
       - `DenyExport(ctx context.Context, requestID uuid.UUID, reviewerID uuid.UUID, note string) error` -- sets status to "denied" with review note.
       - `ExecuteExportAsync(ctx context.Context, requestID uuid.UUID)` -- set status to "processing", call ExecuteExport with all registered handlers, generate download_token (32-byte random hex), set download_expires_at to 7 days, store result, set status to "ready". Log errors, set status to "failed" on error.
       - `GetExportDownload(ctx context.Context, token string) ([]byte, error)` -- look up by download_token, verify not expired, mark as downloaded, return ZIP data.

       Erasure methods:
       - `PreviewErasure(ctx context.Context, targetUserID uuid.UUID) ([]*models.ModuleErasurePreview, error)` -- calls PreviewErasure on each registered handler, returns aggregated list.
       - `ExecuteErasure(ctx context.Context, targetUserID uuid.UUID, executedBy uuid.UUID, moduleActions map[string]string) error`:
         a. Get next anonymized label ("Geloeschter Benutzer #NNN")
         b. For each handler: get action from moduleActions map (default "anonymize"), call ExecuteErasure
         c. Compute confirmation hash: SHA-256 of targetUserID|executedBy|timestamp|moduleActions JSON
         d. Create erasure log entry
         e. Return nil on success

       Important: ExecuteErasure should run in a transaction-like manner. If any module handler fails, log the error and continue with remaining modules (partial erasure is better than no erasure for DSGVO compliance). Record which modules succeeded and which failed in the modules_affected JSONB.
  </action>
