Create `backend/proto/email/v1/email.proto` defining `email.v1.EmailService` with go_package `github.com/kmuhub/kmuhub/proto/email/v1;emailv1`. Define ~35 RPCs covering:

**Account management (5 RPCs):**
- CreateEmailAccount, GetEmailAccount, UpdateEmailAccount, DeleteEmailAccount, TestEmailConnection
- Account messages: imap_host, imap_port, smtp_host, smtp_port, username, password (plaintext in proto -- encrypted at service layer), email_address, display_name, use_ssl, sync_enabled

**Folder operations (3 RPCs):**
- ListFolders, GetFolder, SyncFolders
- Folder messages: id, account_id, name, imap_name, folder_type (inbox/sent/drafts/trash/spam/archive/custom), uid_validity, message_count, unread_count, sort_order

**Message operations (8 RPCs):**
- ListMessages (with folder_id, page, per_page, search query), GetMessage, GetThreadMessages, MarkRead, MarkUnread, ToggleStar, MoveToFolder, DeleteMessage
- Message messages: id, account_id, folder_id, uid, message_id_header, in_reply_to, references (repeated string), thread_id, from (EmailAddress), to/cc/bcc (repeated EmailAddress), subject, preview, body_text, body_html, is_read, is_starred, is_draft, has_attachments, date, size_bytes, attachments (repeated EmailAttachment)
- EmailAddress message: name, email
- EmailAttachment message: id, filename, content_type, size_bytes, minio_key, content_id, is_inline

**Send/compose operations (4 RPCs):**
- SendEmail, SaveDraft, ReplyEmail, ForwardEmail
- SendEmailRequest: account_id, to/cc/bcc (repeated EmailAddress), subject, body_html, body_text, attachment_ids (repeated string), in_reply_to_message_id (optional -- for threading), signature_id (optional)
- ReplyEmailRequest: account_id, original_message_id, body_html, body_text, reply_all (bool), attachment_ids
- ForwardEmailRequest: account_id, original_message_id, to (repeated EmailAddress), body_html, body_text, attachment_ids

**Signature operations (5 RPCs):**
- CreateSignature, GetSignature, ListSignatures, UpdateSignature, DeleteSignature, SetDefaultSignature
- Signature messages: id, user_id, name, html_content, is_default

**CRM linking operations (4 RPCs):**
- GetEmailContactLinks, LinkEmailToContact, UnlinkEmailFromContact, GetContactEmails (get all emails for a CRM contact)
- EmailContactLink message: id, message_id, contact_id, link_type (auto/manual)

**Sync operations (3 RPCs):**
- TriggerSync (force sync for a user's account), GetSyncStatus, SetReadFlag (push read/unread to IMAP server)

**Attachment operations (2 RPCs):**
- UploadAttachment (returns minio_key), GetAttachmentDownloadURL (returns presigned URL)

**Contact import/export (4 RPCs):**
- ImportContactsCSV, ImportContactsVCard, ExportContactsCSV, ExportContactsVCard
- ImportRequest: file_content (bytes), field_mapping (map<string, string>), visibility (shared/personal), merge_by_email (bool)
- ImportResponse: imported_count, merged_count, skipped_count, errors (repeated ImportError)
- ExportRequest: contact_ids (repeated string), fields (repeated string), format (csv/vcard)
- ExportResponse: file_content (bytes), filename

**Migration 000041 (create_email_tables):**

Create up migration with 7 tables exactly as specified in RESEARCH.md database schema section:
1. `email_accounts` -- one per user, vault-encrypted IMAP/SMTP credentials, UNIQUE(user_id)
2. `email_folders` -- IMAP folder cache, UNIQUE(account_id, imap_name), folder_type enum (inbox/sent/drafts/trash/spam/archive/custom)
3. `email_messages` -- full email cache with envelope fields, UNIQUE(folder_id, uid), indexes on account_id, folder_id, thread_id, date DESC, message_id, from_email
4. `email_contact_links` -- junction table linking email messages to CRM contacts, link_type (auto/manual), UNIQUE(message_id, contact_id)
5. `email_attachments` -- attachment metadata with minio_key, content_id for inline images
6. `email_signatures` -- per-user HTML signatures with is_default flag
7. Add a `search_vector tsvector` column to email_messages with GIN index, plus a trigger to auto-update it from subject + body_text + from_name + from_email (same pattern as CRM contact search)

Down migration drops all 7 tables in reverse dependency order and removes the search_vector trigger.

Naming convention: `idx_{table}_{column}` for all indexes (per CLAUDE.md).
