**extractor.go:**
Create the `Extractor` struct that wraps docconv for text extraction:

```go
type Extractor struct {
    maxBytes int64 // max bytes to index (truncate beyond this)
}

func NewExtractor(maxIndexBytes int64) *Extractor
```

Methods:
- `CanExtract(mimeType string) bool` — return true for extractable MIME types: application/pdf, application/msword, application/vnd.openxmlformats-officedocument.wordprocessingml.document, application/vnd.ms-excel, application/vnd.openxmlformats-officedocument.spreadsheetml.sheet, application/vnd.ms-powerpoint, application/vnd.openxmlformats-officedocument.presentationml.presentation, text/plain, text/csv, text/markdown, text/html, application/rtf. Use a map for O(1) lookup. Normalize mimeType to lowercase before checking.
- `Extract(ctx context.Context, reader io.Reader, mimeType string) (string, error)` — call `docconv.Convert(reader, mimeType, false)`, return res.Body truncated to maxBytes. Log extraction errors at Warn level (don't fail the upload). Return empty string on error (search just won't find content).

Default maxIndexBytes: 1MB (1048576). This covers most business documents while keeping the tsvector index manageable.

**postgres_repository.go:**
Implement Search using PostgreSQL full-text search:
```sql
SELECT f.*, ts_rank_cd(f.search_vector, plainto_tsquery('german', $1), 32) AS rank,
       ts_headline('german', coalesce(f.filename || ' ' || coalesce(f.content_text, ''), ''),
                   plainto_tsquery('german', $1),
                   'StartSel=<<, StopSel=>>, MaxWords=35, MinWords=15') AS snippet
FROM document_files f
WHERE f.search_vector @@ plainto_tsquery('german', $1)
  AND f.is_deleted = FALSE
  {AND f.folder_id = $folderFilter}
  {AND f.owner_id = $ownerFilter}
  {AND EXISTS (SELECT 1 FROM document_file_tags dft WHERE dft.file_id = f.id AND dft.tag_id = ANY($tagFilter))}
ORDER BY rank DESC
LIMIT $limit OFFSET $offset
```

Use `ts_rank_cd` with normalization 32 (divide by rank + 1) per research recommendation. Use `ts_headline` for generating result snippets. Build query dynamically based on which filters are provided.

**postgres_repository.go:** Implement virtual folder queries:
- `ListChatFiles`: Query chat_files JOIN channels JOIN channel_members WHERE channel_members.user_id = $userID AND chat_files.is_deleted = FALSE. Map to VirtualFile with source_type="chat", source_name=channel.name. Use COUNT(*) OVER() for total.
- `ListEmailAttachments`: Query email_attachments JOIN email_messages JOIN email_accounts WHERE email_accounts.user_id = $userID. Map to VirtualFile with source_type="email", source_name=folder_name or subject snippet.
- `ListTaskFiles`: Query task_files JOIN tasks JOIN project_members WHERE project_members.user_id = $userID (for project tasks) OR tasks.assignee_id = $userID (for standalone). Map to VirtualFile with source_type="task", source_name=task title.
- `ListAll`: UNION ALL of the three queries above, filtered by optional sourceType parameter. Order by created_at DESC. Paginate the union.

Per user decision: auto-surface all existing attachments (no explicit "save to files" step). Virtual folders are read-only views.
