  <action>
    Create `repository.go` with the Repository interface:
    ```go
    type Repository interface {
        AddReaction(ctx context.Context, messageID, userID uuid.UUID, emoji string) error
        RemoveReaction(ctx context.Context, messageID, userID uuid.UUID, emoji string) error
        ReactionExists(ctx context.Context, messageID, userID uuid.UUID, emoji string) (bool, error)
        ListReactions(ctx context.Context, messageID uuid.UUID) ([]Reaction, error)
        GetReactionSummary(ctx context.Context, messageID, currentUserID uuid.UUID) ([]ReactionSummary, error)
        GetBatchReactionSummary(ctx context.Context, messageIDs []uuid.UUID, currentUserID uuid.UUID) (map[uuid.UUID][]ReactionSummary, error)
    }
    ```

    Create `postgres_repository.go` implementing the interface:

    - `AddReaction`: INSERT INTO message_reactions (message_id, user_id, emoji) VALUES ($1, $2, $3). Use ON CONFLICT DO NOTHING (composite PK prevents duplicates).
    - `RemoveReaction`: DELETE FROM message_reactions WHERE message_id=$1 AND user_id=$2 AND emoji=$3.
    - `ReactionExists`: SELECT EXISTS(SELECT 1 FROM message_reactions WHERE ...).
    - `ListReactions`: SELECT * FROM message_reactions WHERE message_id=$1 ORDER BY created_at ASC.
    - `GetReactionSummary`: Aggregate query that groups by emoji, counts users, collects user_ids array, and checks if current user is in the list:
      ```sql
      SELECT emoji, COUNT(*) as count,
             array_agg(user_id ORDER BY created_at) as user_ids,
             bool_or(user_id = $2) as current_user_reacted
      FROM message_reactions WHERE message_id = $1
      GROUP BY emoji ORDER BY MIN(created_at)
      ```
    - `GetBatchReactionSummary`: Same aggregation but with `WHERE message_id = ANY($1)`, returns map keyed by message_id. Use a single query with message_id in the GROUP BY.

    Follow existing repository patterns (see comment/repository.go). Use `pgx.Pool` for DB access.
  </action>

    `cd backend && go build ./internal/work/reaction/...` compiles without errors.
  </verify>
  <done>
    Repository interface defined with 6 methods. PostgreSQL implementation handles toggle semantics, per-message summaries, and batch summaries. Composite PK prevents duplicate reactions.
  </done>
