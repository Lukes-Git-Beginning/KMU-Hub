    **Store interface and Redis implementation** (`redis_store.go`):
    ```go
    type Store interface {
        SetPresence(ctx context.Context, userID string, status PresenceStatus, manual bool) error
        GetPresence(ctx context.Context, userID string) (*UserPresence, error)
        GetBulkPresence(ctx context.Context, userIDs []string) (map[string]*UserPresence, error)
        RemovePresence(ctx context.Context, userID string) error
        UpdateLastActivity(ctx context.Context, userID string) error
    }
    ```

    Redis implementation (`RedisStore`):
    - Key format: `presence:{userID}` -> JSON `{"status":"online","manual":false,"last_activity":1234567890,"updated_at":1234567890}`
    - TTL: 90 seconds (3x heartbeat interval per research)
    - SetPresence: SET with 90s TTL
    - GetPresence: GET + JSON unmarshal. If key not found, return UserPresence with status=Offline
    - GetBulkPresence: Use Redis Pipeline for batch GET. Return map, missing keys = Offline
    - RemovePresence: DEL key (immediate offline)
    - UpdateLastActivity: GET current presence, update last_activity timestamp, SET back with remaining TTL

    Constructor: `NewRedisStore(client *redis.Client) *RedisStore`

    **Service** (`service.go`):
    ```go
    type ConfigRepository interface {
        GetConfig(ctx context.Context) (*PresenceConfig, error)
        UpdateConfig(ctx context.Context, awayTimeoutSeconds int, updatedBy uuid.UUID) error
    }

    type Service struct {
        store      Store
        configRepo ConfigRepository
    }
    ```

    Methods:
    - `Heartbeat(ctx, userID string) error`:
      1. Get current presence
      2. If not exists or was offline: SetPresence with status=Online, manual=false
      3. If exists and not manual override: update last_activity, renew TTL
      4. If manual override (DND): just renew TTL without changing status

    - `GetPresence(ctx, userID string) (*UserPresence, error)`:
      1. Get from store
      2. If status is online and not manual: check if last_activity + away_timeout < now
      3. If away timeout exceeded: return away status (but don't write it -- lazy evaluation)
      4. Return presence

    - `GetBulkPresence(ctx, userIDs []string) (map[string]*UserPresence, error)`:
      1. Get bulk from store
      2. Get away_timeout from config (cache in memory, refresh every 60s)
      3. Apply away detection to each non-manual user
      4. Return map

    - `SetManualStatus(ctx, userID string, status PresenceStatus) error`:
      Must be Online, Away, or DND. In_Call is automatic only, Offline means disconnect.
      Set with manual=true.

    - `SetInCall(ctx, userID string) error`:
      Set status=InCall, manual=false. Called by LiveKit webhook handler.

    - `ClearInCall(ctx, userID string) error`:
      If current status is InCall: set back to Online. Otherwise leave as is (user might have set DND).

    - `Disconnect(ctx, userID string) error`:
      Remove presence key entirely. User goes offline.

    - `GetConfig(ctx) (*PresenceConfig, error)`: Delegate to configRepo.

    - `UpdateConfig(ctx, awayTimeoutSeconds int, updatedBy uuid.UUID) error`:
      Validate: awayTimeoutSeconds must be >= 60 and <= 3600 (1 min to 1 hour).
      Update via configRepo.

    Cache away_timeout in Service struct with 60-second refresh to avoid DB hit on every GetPresence call. Use sync.RWMutex + time.Time for last fetch.

    **Config repository** -- Add a simple implementation in presence package:

    ```go
    type PostgresConfigRepository struct {

    }
    ```
    - GetConfig: SELECT away_timeout_seconds FROM presence_config LIMIT 1
    - UpdateConfig: UPDATE presence_config SET away_timeout_seconds=$1, updated_by=$2, updated_at=NOW()
