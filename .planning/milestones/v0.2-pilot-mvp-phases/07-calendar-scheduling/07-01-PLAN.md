IMPORTANT: The resource_id FK in calendar_events references resources table which is created in migration 000034. Since migrations run sequentially and PostgreSQL supports forward-referencing through ALTER TABLE, either:
- Option A: Remove the resource_id FK constraint from 000033 and add it in 000034 via ALTER TABLE
- Option B: Move resource_id column to an ALTER TABLE in 000034
Choose Option A for cleaner event table definition -- add resource_id column WITHOUT FK in 000033, then add FK constraint in 000034 after resources table exists.

- down.sql: DROP TABLE user_calendar_preferences, event_reminders, event_exceptions, event_attendees, calendar_events
