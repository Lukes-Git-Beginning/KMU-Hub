# Plan 20-03: Extension Points + gRPC Plugin API

## Objective

Build the hook dispatcher, workflow engine, gRPC service (32 RPCs), gateway routes, and frontend admin UI.

## Deliverables

1. **Hook dispatcher** (plugin/hook/dispatcher.go) -- Before-hooks (sequential pipe) + after-hooks (parallel fire-and-forget)
2. **Workflow engine** (plugin/config/workflow_engine.go) -- Condition evaluation (12 operators) + action execution (4 types)
3. **Proto definition** (plugin/v1/plugin.proto) -- 32 RPCs across 8 service categories
4. **Plugin service** (plugin/service.go) -- Central business logic orchestrating all operations
5. **gRPC server** (server/plugin_grpc.go) -- All 32 RPCs implemented
6. **Gateway routes** (gateway/route_plugin.go) -- 26 HTTP endpoints under /api/v1/plugins/*
7. **Frontend: Plugin management** -- PluginListPage, PluginDetailDialog, PermissionApprovalDialog, PluginSettingsEditor
8. **Frontend: Rule editors** -- ValidationRulesEditor, WorkflowRulesEditor
9. **API client + types** -- plugin-client.ts, plugin-types.ts, usePlugins.ts hooks

## Key Design Decisions

- Before-hooks: sequential pipe pattern (data flows through plugins in priority order)
- After-hooks: parallel fire-and-forget (failures don't block)
- Workflow conditions: 12 operators (eq, neq, gt, lt, gte, lte, contains, starts_with, ends_with, exists, not_exists)
- Workflow actions: create_task, send_notification, set_field, log with {{field}} template substitution
- Plugin service on standalone binary :50060 (gRPC) / :9100 (health)
- Admin-only mutations, read access for all authenticated users
