**postgres_repository.go:**
Implement all methods using pgx/v5.

Critical implementation details:
- `Create`: Use `UPDATE projects SET next_task_number = next_task_number + 1 WHERE id = $1 RETURNING next_task_number - 1` to atomically get the next task number. For standalone tasks (project_id is nil), use a system counter or a dedicated "standalone" project row (research recommends project key "TASK").
- `GetByID`: Single query with LEFT JOINs to project_statuses, users (assignee), projects. Subquery for subtask_count: `(SELECT COUNT(*) FROM tasks WHERE parent_task_id = t.id)`. Subquery for has_blocked_deps: `EXISTS(SELECT 1 FROM task_dependencies WHERE target_task_id = t.id AND dependency_type = 'blocks')`.
- `List`: Build query dynamically based on filters. Use parameterized placeholders. JOIN for relations. Support sorting by created_at, due_date, priority, title, task_number. Pagination via LIMIT/OFFSET.
- `GetSubtasks`: Recursive CTE (see research doc for exact SQL). Limit depth to parameter.
- `HasCycle`: Recursive CTE traversing dependency graph from targetID to check if it reaches sourceID (see research doc).
- `Search`: `WHERE search_vector @@ plainto_tsquery('german', $1)` with `ts_rank` ordering. Apply additional filters (project_ids, assignee_ids, etc.) as AND clauses.
- `MoveTask`: Single UPDATE setting status_id and sort_order. Also update updated_at.
- All list queries include ORDER BY with configurable sort.
- N+1 prevention: List queries JOIN all necessary relations in one query.

**event_emitter.go:**
Follow `crm/deal/event_emitter.go` pattern exactly:

```go
type EventEmitter interface {
    EmitTaskEvent(ctx context.Context, payload models.EventPayload) error
}

type PGEventEmitter struct {
    pool *pgxpool.Pool
}

func NewPGEventEmitter(pool *pgxpool.Pool) *PGEventEmitter {
    return &PGEventEmitter{pool: pool}
}

func (e *PGEventEmitter) EmitTaskEvent(ctx context.Context, payload models.EventPayload) error {
    return event.EmitEvent(ctx, e.pool, payload)
}
```

**service.go:**
Service struct: `repo Repository`, `projectRepo project.Repository` (for membership checks), `eventEmitter EventEmitter` (optional, set via SetEventEmitter).

Constructor: `NewService(repo Repository, projectRepo project.Repository) *Service`

Key business logic methods:

`Create(ctx, input CreateInput) (*models.TaskWithRelations, error)`:
- Validate title (1-500 chars), priority (must be in ValidPriorities)
- If project_id provided: check user is member (not viewer) via projectRepo.IsMember/GetMember
- If parent_task_id provided: get parent depth, enforce max depth (5). Set depth = parent.depth + 1. Ensure parent is in same project.
- Create task via repo (gets atomic task_number)
- Log activity: ActionCreated
- Emit event: `work.task.created` if assignee != creator

`Update(ctx, taskID uuid.UUID, input UpdateInput, actorID uuid.UUID) (*models.TaskWithRelations, error)`:
- Get existing task. Check project membership.
- For each changed field, log activity with old/new values.
- If status changed: emit `work.task.status_changed` event
- If assignee changed: emit `work.task.assigned` event to new assignee
- If priority changed: log activity
- If due_date changed: log activity
- Update task via repo

`MoveTask(ctx, taskID uuid.UUID, newStatusID uuid.UUID, newSortOrder float64, actorID uuid.UUID)`:
- Get task. Check project membership. Get old status.
- Update via repo.MoveTask
- Log activity: ActionStatusChanged with old/new status
- Emit event: `work.task.status_changed`
- If new status is_closed: set completed_at. If moving from closed to open: clear completed_at.

`Delete(ctx, taskID uuid.UUID, actorID uuid.UUID)`:
- Check project membership (owner/member, not viewer).
- Delete cascades subtasks via FK.

`CreateDependency(ctx, input DepInput)`:
- Validate dependency_type
- Check self-dependency (source == target)
- Check duplicate
- If type is "blocks" or "blocked_by": run cycle detection via repo.HasCycle
- Create dependency

`ListMyTasks(ctx, userID uuid.UUID, filters)`:
- Query tasks where assignee_id = userID OR created_by = userID (for standalone tasks)
- Include tasks from all projects user is member of

`GetSubtreeForTemplate(ctx, projectID uuid.UUID)`:
- Get all tasks for a project with their parent relationships
- Used by template instantiation to copy task hierarchy

`CreateFromTemplate(ctx, sourceProjectID, targetProjectID uuid.UUID, actorID uuid.UUID)`:
- Get all tasks from source project
- Copy in topological order (parents before children)
- Maintain old_id -> new_id mapping for parent_task_id remapping
- Copy dependencies using same mapping
- Set new task numbers from target project counter

Event types to emit (add to `notification/event/types.go` -- update that file):
- `work.task.created` -- when task created with assignee != creator
- `work.task.assigned` -- when assignee changes
- `work.task.status_changed` -- when status changes
- `work.task.commented` -- when comment added (emitted by comment service)
- `work.task.mentioned` -- when @mention in comment
