**useTaskComments.ts:**
```typescript
// Queries
export function useTaskComments(taskId: string, page?: number) -- GET /api/v1/tasks/{id}/comments

// Mutations
export function useCreateComment() -- POST /api/v1/tasks/{id}/comments { content, quoted_comment_id? }
export function useUpdateComment() -- PUT /api/v1/tasks/{id}/comments/{commentId} { content }
export function useDeleteComment() -- DELETE /api/v1/tasks/{id}/comments/{commentId}
```

Interfaces:
```typescript
interface TaskComment {
  id: string; task_id: string; author_id: string; author_name: string;
  content: string; quoted_comment_id?: string; quoted_content_preview?: string;
  created_at: string; updated_at: string;
}
```

Invalidation: mutations invalidate ['task-comments', taskId] and ['task-activities', taskId] (since commenting creates an activity entry).

**useTaskActivities.ts:**
```typescript
export function useTaskActivities(taskId: string, page?: number) -- GET /api/v1/tasks/{id}/activities
```

Interface:
```typescript
interface TaskActivity {
  id: string; task_id: string; actor_id: string; actor_name: string;
  action: string; field_name?: string;
  old_value?: string; new_value?: string;
  created_at: string;
}
```

**useTaskFiles.ts:**
```typescript
// Queries
export function useTaskFiles(taskId: string) -- GET /api/v1/tasks/{id}/files

// Mutations
export function useAttachFile() -- POST /api/v1/tasks/{id}/files (multipart FormData)
export function useRemoveFile() -- DELETE /api/v1/tasks/{id}/files/{fileId}
```

File upload mutation must use FormData (not JSON). The hook should accept a File object and construct the multipart request. Follow the pattern from chat file upload if one exists in the hooks.

```typescript
interface TaskFile {

  file_size: number; storage_key: string; thumbnail_key?: string;
  uploaded_by: string; uploaded_by_name: string; created_at: string;
}
```

**ActivityLog.tsx:**
Props: `taskId: string`

Displays activities from useTaskActivities. Each entry shows:
- Icon based on action type (status_changed: arrows, assigned: user, priority_changed: flag, etc.)
- Actor name
- Description: formatted based on action type:
  - status_changed: "{actor} hat den Status von {old} zu {new} geaendert"
  - assigned: "{actor} hat {new} zugewiesen" (or "hat die Zuweisung entfernt")
  - priority_changed: "{actor} hat die Prioritaet von {old} auf {new} geaendert"
  - created: "{actor} hat die Aufgabe erstellt"
  - commented: "{actor} hat kommentiert" (this is the link to the actual comment in the interleaved view)
  - attachment_added: "{actor} hat {filename} angehängt"
  - linked/unlinked: "{actor} hat {entity} verknuepft/entfernt"
- Timestamp (relative)

Status changes are more prominent (larger, with color-coded indicators per discretion recommendation).
