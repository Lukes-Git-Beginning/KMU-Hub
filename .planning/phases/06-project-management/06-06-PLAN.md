**TaskListView.tsx:**
Main list view component. Props: `projectId`, `statuses`.

Uses useTasks hook with project_id filter. Applies grouping client-side based on selected group_by dimension:
- Group by status: group tasks by status_id, render group headers with StatusBadge
- Group by assignee: group by assignee_id, headers show avatar + name
- Group by priority: group by priority value, headers show PriorityBadge
- Group by due date: group into "Overdue", "Today", "This Week", "Later", "No Date"
- None: flat list

Each group is collapsible (expand/collapse with animation).

Within each group, tasks sorted by the sort_by preference (default: sort_order for status grouping, created_at for others).

Subtask nesting: Top-level tasks (parent_task_id is null) shown first. Each can be expanded to show subtasks (loaded via useSubtasks or included in initial response). Multi-level collapse/expand per locked decision.

Skeleton loading: Rows with placeholder blocks matching column widths.

**KanbanBoard.tsx:**
The main Kanban board. Props: `projectId`, `statuses`, `tasks`.

Setup:
```typescript
const sensors = useSensors(
  useSensor(PointerSensor, { activationConstraint: { distance: 5 } }),
  useSensor(KeyboardSensor, { coordinateGetter: sortableKeyboardCoordinates })
)
```

Group tasks by status_id into columns. Each column is a SortableContext with verticalListSortingStrategy.

Event handlers:
- `onDragStart`: Set active task for DragOverlay
- `onDragOver`: Handle cross-container movement (card hovering over different column). Optimistically move card in local state.
- `onDragEnd`: Finalize move. Calculate new sort_order using fractional ordering (midpoint between neighbors, or 1.0 if empty column). Call useMoveTask mutation with optimistic update:
  ```typescript
  queryClient.setQueryData(['tasks', { project_id: projectId }], (old) =>
    old?.map(t => t.id === taskId ? { ...t, status_id: newStatusId, sort_order: newSortOrder } : t)
  )
  ```
  On error: invalidate queries (causes refetch, card snaps back) + toast error: "Status konnte nicht geaendert werden".

DragOverlay: Renders KanbanCard with `isDragOverlay` prop for elevated shadow styling.

Collision detection: `closestCorners` from @dnd-kit (best for multi-container scenarios).

Multi-level subtasks on Kanban: Top-level tasks only shown as cards. Subtask count displayed on card. Expanding subtasks on Kanban is NOT shown (per research: too complex for board view). Subtasks are managed via list view or detail panel.
