    **route_video.go:**
    Create `VideoRoutes` implementing `RouteRegistrar` (same pattern as route_work.go, route_chat.go).

    Register HTTP routes under `/api/v1/`:

    **Call endpoints:**
    - `POST /calls` -- create a new call (body: call_type, channel_id, max_participants)
    - `GET /calls/active` -- list active calls
    - `GET /calls/history` -- get call history for authenticated user (query: offset, limit)
    - `GET /calls/{callId}` -- get call details with participants
    - `POST /calls/{callId}/join` -- join a call (returns token + ws_url)
    - `POST /calls/{callId}/leave` -- leave a call
    - `POST /calls/{callId}/end` -- end a call
    - `POST /calls/from-chat/{channelId}` -- start call from chat channel/DM
    - `GET /calls/livekit-url` -- get LiveKit WebSocket URL for frontend

    **Recording endpoints:**
    - `POST /calls/{callId}/recordings` -- request recording (triggers consent)
    - `DELETE /calls/{callId}/recordings/active` -- stop active recording
    - `POST /calls/{callId}/recordings/consent` -- submit consent (body: consented bool)
    - `GET /calls/{callId}/recordings` -- list recordings for a call
    - `GET /recordings/{recordingId}` -- get recording details

    **Meeting endpoints:**
    - `POST /meetings` -- create meeting
    - `GET /meetings` -- list meetings (query: status, from, to, offset, limit)
    - `GET /meetings/{meetingId}` -- get meeting details
    - `PUT /meetings/{meetingId}` -- update meeting
    - `DELETE /meetings/{meetingId}` -- cancel meeting
    - `POST /meetings/{meetingId}/rsvp` -- RSVP response
    - `POST /meetings/{meetingId}/start` -- start meeting (returns token)
    - `POST /meetings/{meetingId}/end` -- end meeting

    **Meeting notes & action items:**
    - `POST /meetings/{meetingId}/notes` -- create note
    - `PUT /meetings/notes/{noteId}` -- update note
    - `GET /meetings/{meetingId}/notes` -- list notes
    - `POST /meetings/{meetingId}/action-items` -- create action item
    - `PUT /meetings/action-items/{itemId}` -- update action item
    - `POST /meetings/action-items/{itemId}/complete` -- complete action item
    - `GET /meetings/{meetingId}/action-items` -- list action items

    **Presence endpoint:**
    - `POST /presence/bulk` -- get bulk presence (body: user_ids array)

    **Reaction endpoints (add to route_chat.go):**
    - `POST /messages/{messageId}/reactions` -- toggle reaction (body: emoji)
    - `GET /messages/{messageId}/reactions` -- get reaction summaries

    Each handler follows the thin handler pattern: parse request, call gRPC, format response. Extract user_id from JWT middleware context (same as existing handlers).

    Add new message type handlers to the existing WebSocket hub:

    Client -> Server:
    - `presence.heartbeat` -- call presenceService.Heartbeat(userID). Process every 30 seconds from each connected client.

    Server -> Client (emitted via pg_notify -> WebSocket broadcast):
    - `presence.update` -- {user_id, status} -- broadcast when user presence changes significantly
    - `call.incoming` -- {call_id, room_name, initiated_by, channel_id} -- sent to target user(s) for incoming call
    - `call.accepted` -- {call_id, user_id} -- sent to caller when callee accepts
    - `call.rejected` -- {call_id, user_id} -- sent to caller when callee rejects
    - `call.ended` -- {call_id} -- sent to all participants when call ends
    - `call.recording.consent_required` -- {call_id, recording_id} -- sent to all participants
    - `call.recording.started` -- {call_id} -- sent to all participants
    - `call.recording.stopped` -- {call_id} -- sent to all participants
    - `reaction.added` -- {message_id, user_id, emoji, reaction_summary} -- sent to channel members
    - `reaction.removed` -- {message_id, user_id, emoji, reaction_summary} -- sent to channel members

    Add a pg_notify listener for a new 'video_events' channel (or reuse 'events' channel with type prefix filtering).
