    **Repository interface** (`repository.go`):
    ```go
    type Repository interface {
        CreateRecording(ctx context.Context, rec *Recording) error
        GetRecording(ctx context.Context, id uuid.UUID) (*Recording, error)
        UpdateRecording(ctx context.Context, rec *Recording) error
        ListRecordingsByCall(ctx context.Context, callID uuid.UUID) ([]Recording, error)
        ListRecordingsByMeeting(ctx context.Context, meetingID uuid.UUID) ([]Recording, error)
        DeleteRecording(ctx context.Context, id uuid.UUID) error
        SetConsent(ctx context.Context, consent *RecordingConsent) error
        GetConsents(ctx context.Context, recordingID uuid.UUID) ([]RecordingConsent, error)
        CountPendingConsents(ctx context.Context, recordingID uuid.UUID, participantIDs []uuid.UUID) (int, error)
        ListExpiredRecordings(ctx context.Context, before time.Time) ([]Recording, error)
        // Phase 11 integration: file manager discovery queries
        ListRecordingsWithAccess(ctx context.Context, userID uuid.UUID, meetingID *uuid.UUID) ([]Recording, error)
        GetRecordingParticipants(ctx context.Context, recordingID uuid.UUID) ([]uuid.UUID, error)
    }
    ```

    **PostgreSQL repository** (`postgres_repository.go`):
    - SetConsent: INSERT ON CONFLICT (recording_id, user_id) DO UPDATE SET consented=$3, responded_at=NOW()
    - CountPendingConsents: Count participants in participantIDs who have NOT responded (LEFT JOIN recording_consents WHERE consented IS NULL)
    - ListExpiredRecordings: WHERE retention_expires_at < $1 AND status = 'completed'
    - **ListRecordingsWithAccess**: Query recordings WHERE status = 'completed' AND the user was a participant in the associated call or meeting. Join through call_participants (for call recordings) or meeting_attendees (for meeting recordings):
      ```sql
      SELECT r.* FROM recordings r
      LEFT JOIN call_participants cp ON r.call_id = cp.call_id AND cp.user_id = $1
      LEFT JOIN meeting_attendees ma ON r.meeting_id = ma.meeting_id AND ma.user_id = $1
      WHERE r.status = 'completed'
        AND (cp.user_id IS NOT NULL OR ma.user_id IS NOT NULL)
        AND ($2::uuid IS NULL OR r.meeting_id = $2)
      ORDER BY r.created_at DESC
      ```
      This enforces the user decision: "Nur Meeting-Teilnehmer haben Zugriff" (only meeting participants have access).
    - **GetRecordingParticipants**: Returns the list of user IDs who have access to a recording (union of call_participants.user_id and meeting_attendees.user_id for the associated call/meeting). Phase 11 file manager will call this to enforce file-level access control.

    **Service** (`service.go`):
    ```go
    type EgressManager interface {
        StartRoomCompositeEgress(ctx context.Context, roomName, templateURL string, s3Config S3Config) (string, error)  // returns egressID
        StopEgress(ctx context.Context, egressID string) error
    }

    type S3Config struct {
        Endpoint, AccessKey, Secret, Bucket string
    }

    type Service struct {
        repo           Repository
        egressManager  EgressManager  // nil if not configured
        minioEndpoint  string
        minioAccessKey string
        minioSecret    string
        minioBucket    string
        templateURL    string
        enabled        bool
    }
    ```

    Methods:
    - `StartRecording(ctx, callID *uuid.UUID, meetingID *uuid.UUID, roomName string, participantIDs []uuid.UUID) (*Recording, error)`:
      1. Create Recording with status=active
      2. Set retention_expires_at = NOW() + 30 days (per user decision)
      3. Set file_path to `recordings/{meetingID or callID}/{roomName}-{timestamp}.mp4` -- structured path enables Phase 11 file manager to group recordings by meeting folder
      4. For each participant, check if consent exists. If any participant has NOT responded, return ErrConsentPending
      5. **DSGVO selective consent via custom egress template:**
         Before starting Egress, set participant metadata on each LiveKit participant in the room:
         - For each participant who declined consent: set metadata `{"recording_consent": false}` via LiveKit UpdateParticipant API
         - For each participant who accepted: set metadata `{"recording_consent": true}`
         The custom egress template (a React app served at templateURL via `CustomBaseUrl` in RoomCompositeEgressRequest) reads this metadata per participant and:
         - For `recording_consent: false`: applies CSS `filter: blur(20px)` on the participant's video tile and mutes their `<audio>` element
         - For `recording_consent: true`: renders video and audio normally
         This approach uses LiveKit's built-in custom template support (documented at docs.livekit.io/home/egress/custom-template/) -- the Egress service loads the template URL, which renders a standard LiveKit room composite but with consent-aware styling.
      6. Start Egress via egressManager.StartRoomCompositeEgress with:
         - roomName: the LiveKit room name
         - templateURL: the custom DSGVO template URL (e.g., `http://gateway:8080/recording-template/`)
         - S3 config pointing to MinIO with structured file path
      7. Store egress_id on recording
      8. Return recording

    - `StopRecording(ctx, recordingID uuid.UUID) (*Recording, error)`:
      1. Get recording, verify status=active
      2. Stop Egress via egressManager
      3. Update status to processing (Egress takes time to finalize)

    - `SetConsent(ctx, recordingID, userID uuid.UUID, consented bool) error`:
      1. Validate recording exists and is in active/pending state
      2. Store consent via repo
      3. Return nil

    - `GetConsentStatus(ctx, recordingID uuid.UUID, participantIDs []uuid.UUID) (allResponded bool, consents []RecordingConsent, error)`:
      1. Get all consents for recording
      2. Check if all participantIDs have responded
      3. Return status

    - `CompleteRecording(ctx, recordingID uuid.UUID, fileURL string, fileSizeBytes int64, durationSeconds int) error`:
      For webhook callback when Egress finishes -- update recording with file info, set status=completed.
      The fileURL and file_path stored on the Recording model enable dual visibility:
      - **Meeting-Detail-Panel:** The frontend queries `ListRecordingsByMeeting(meetingID)` and shows recordings inline in MeetingDetailPanel.tsx (already wired in 08-08)
      - **Phase 11 central file manager:** Will call `ListRecordingsWithAccess(userID, meetingID)` to discover recordings under a virtual "Meeting-Ordner" (meeting folder), enforcing participant-only access via the JOIN-based query

    - `FailRecording(ctx, recordingID uuid.UUID, reason string) error`:
      For webhook callback when Egress fails -- set status=failed.

    - `CleanupExpiredRecordings(ctx context.Context) (int, error)`:
      1. List expired recordings via repo.ListExpiredRecordings(time.Now())
      2. For each: delete from MinIO (via S3 API), set status=deleted
      3. Return count of cleaned up recordings
      Note: This will be called by a periodic goroutine or cron (wired in 08-05)

    - `ListRecordings(ctx, callID *uuid.UUID, meetingID *uuid.UUID) ([]Recording, error)`: Delegate based on which ID is provided.

    - `ListRecordingsWithAccess(ctx, userID uuid.UUID, meetingID *uuid.UUID) ([]Recording, error)`:
      Delegate to repo. This is the Phase 11 integration method -- returns only recordings the user has access to (was a participant in the call/meeting). If meetingID is provided, scoped to that meeting's folder.

    - `GetRecordingParticipants(ctx, recordingID uuid.UUID) ([]uuid.UUID, error)`:
      Delegate to repo. Returns list of user IDs with access. Phase 11 file manager uses this for per-file ACL checks.
