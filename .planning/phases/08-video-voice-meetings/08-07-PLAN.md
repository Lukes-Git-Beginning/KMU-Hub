    **Electron preload extension (preload/index.ts):**
    Add a new IPC bridge for screen sharing. Extend the existing contextBridge.exposeInMainWorld call (or add a new one) to expose:
    ```typescript
    electronScreenShare: {
      getSources: () => ipcRenderer.invoke('get-desktop-sources')
    }
    ```
    In the main process (if needed, add an ipcMain handler):
    ```typescript
    ipcMain.handle('get-desktop-sources', async () => {
      const { desktopCapturer } = require('electron');
      const sources = await desktopCapturer.getSources({
        types: ['window', 'screen'],
        thumbnailSize: { width: 320, height: 180 },
      });
      return sources.map(s => ({
        id: s.id,
        name: s.name,
        thumbnail: s.thumbnail.toDataURL(),
      }));
    });
    ```
    Also add the type declaration for `window.electronScreenShare` in the renderer's type definitions.

    **CallNotification.tsx:**
    Incoming call overlay notification.
    - Reads `incomingCall` from useCallStore
    - If incomingCall is set, render a notification card at top-right of screen
    - Shows: caller name (resolve from user data), call type indicator (video/audio)
    - Two buttons: Accept (green, Phone icon) and Reject (red, PhoneOff icon)
    - Accept: calls useJoinCall with the callId, sets active call in store, clears incoming
    - Reject: sends WebSocket message `call.rejected`, clears incomingCall from store
    - Auto-dismiss after 30 seconds (timeout -> treat as missed call)
    - Sound: play a notification sound (use Audio API with a simple ring tone -- store a ring.mp3 in assets or use Web Audio API for a generated tone)
    - Style: fixed position top-right, z-index above other content, slide-in animation, rounded card with shadow
    - Pulsing accept button for visual urgency

    Register WebSocket listener for `call.incoming` messages:
    - When received, set incomingCall in store: { callId, initiatedBy, channelId }
    - Only show if user is not already in a call (check activeCall in store)

    **FloatingCallBar.tsx:**
    Minimized call indicator when user navigates away from the call view.
    - Only visible when activeCall is set AND isMinimized is true
    - Shows: call duration timer (count up from call start), participant count, call status
    - Buttons: Expand (opens full VideoCallView again), Mute toggle, Hang up
    - Style: fixed bottom-right corner, small rounded bar, dark background with accent border
    - Duration timer: use requestAnimationFrame or setInterval (1s) counting from call startedAt
    - Click anywhere on the bar (except buttons) expands the call
    - Subtle pulsing border if recording is active

    **RecordingConsentDialog.tsx:**
    DSGVO-compliant recording consent dialog.
    - Triggered when WebSocket receives `call.recording.consent_required`
    - Or when user clicks Record button (which sends the request, then all participants see consent dialog)
    - Shows: "Aufnahme angefragt" / "Recording Requested" header
    - Body: DSGVO notice text explaining that the call will be recorded, what data is captured, and storage info
    - Text (German): "Ein Teilnehmer moechte dieses Gespraech aufnehmen. Die Aufnahme wird sicher auf dem Server gespeichert. Gemaess DSGVO benoetigen wir die Zustimmung aller Teilnehmer."
    - Two buttons: "Zustimmen" (Consent) -- green, "Ablehnen" (Decline) -- red
    - On consent/decline: calls useSubmitConsent mutation with { callId, consented: true/false }
    - Shows consent progress: "3 von 5 Teilnehmer haben zugestimmt" with checkmarks/X per participant
    - If any participant declines: show "Aufnahme abgelehnt" message and close
    - If all consent: show "Aufnahme startet..." briefly, then close (recording starts automatically on backend)
    - Use Radix Dialog for modal. Blocking (cannot interact with call while consent dialog is open).

    Register WebSocket listeners:
    - `call.recording.consent_required` -> open consent dialog, set consentPending in store
    - `call.recording.started` -> close dialog if open, set isRecording in store
    - `call.recording.stopped` -> clear isRecording in store

    All three components should be rendered at the app shell level (not inside a specific page) so they overlay correctly:
    - CallNotification always mounted, visibility controlled by store
    - FloatingCallBar always mounted, visibility controlled by store
    - RecordingConsentDialog always mounted, visibility controlled by store
