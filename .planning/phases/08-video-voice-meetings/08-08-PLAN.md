    **MeetingListPage.tsx:**
    Main meetings module page (route: /meetings in the app router).

    Layout:
    - Header: "Meetings" title + "Neues Meeting" button (opens MeetingScheduleForm dialog)
    - Filter bar: status tabs (Alle, Geplant, Aktiv, Abgeschlossen, Abgesagt)
    - Meeting list: card-based list showing meetings sorted by scheduled_start
    - Each card shows: title, scheduled time, attendee count, status badge, organizer avatar
    - Click on card -> navigate to meeting detail (lobby for scheduled, summary for completed)
    - Empty state: "Keine Meetings geplant" with illustration and create button

    Data: uses useMeetings(filters) hook with status filter from tabs.
    Pagination: load more button or infinite scroll (match existing list patterns).

    Status badges:
    - Geplant (blue), Aktiv (green pulsing), Abgeschlossen (gray), Abgesagt (red strikethrough)

    Each card also shows:
    - Relative time: "In 2 Stunden" or "Gestern um 14:00"
    - RSVP summary: "3 zugesagt, 1 ausstehend"
    - Quick actions: Join (if scheduled/active, user is attendee), Cancel (if organizer)

    **MeetingScheduleForm.tsx:**
    Meeting creation and editing dialog.

    Fields:
    - Title (required, text input)
    - Description (optional, textarea)
    - Agenda (optional, textarea with placeholder "Agenda-Punkte fuer das Meeting...")
    - Date + Start time + End time (date picker + time pickers)
    - Attendees (user search/select component -- reuse the user picker pattern from existing task assignee or event attendee components)
    - Meeting type (dropdown: Standard, Einmalig, Wiederkehrend -- disabled for now, always standard)
    - Calendar event link (optional, if creating from calendar context -- hidden field)
    - CRM entity link (optional -- entity type + entity ID, for linking to deal/contact)

    Validation:
    - Title required, max 500 chars
    - End time must be after start time
    - At least 1 attendee (besides organizer)
    - Start time must be in the future (for new meetings)

    Submit: calls useCreateMeeting or useUpdateMeeting mutation. On success, invalidate meetings query, close dialog, show success toast (if toast system available, otherwise console.log).

    Edit mode: same form pre-filled with existing meeting data. Props: meeting?: Meeting (if set, edit mode).

    Use Radix Dialog as the container. Form follows existing form patterns (controlled inputs with React state or react-hook-form if in use).

    **index.ts:**
    Barrel exports for all meeting components.

    **MeetingLobby.tsx:**
    Pre-meeting view (shown when navigating to a scheduled meeting).
    Props: meetingId: string.

    Layout:
    - Meeting title as page header
    - Two-column layout (or stacked on smaller screens):
      - Left: Agenda display (rendered as a formatted text block, or as bullet points if agenda contains line breaks)
      - Right: Attendee list with RSVP status icons (check = accepted, X = declined, ? = pending, ~ = tentative)
    - Meeting details: date/time, duration, organizer name
    - Bottom action bar:
      - "Meeting starten" button (green, only for organizer, only when status=scheduled) -- calls useStartMeeting, which creates LiveKit room and sets active call in store, opening VideoCallView
      - "Beitreten" button (for attendees, only when status=active) -- calls useJoinCall with meeting's call_id
      - "RSVP aendern" buttons (Zusagen / Absagen / Vielleicht)

    If meeting is active (already started): show a prominent "Beitreten" banner at top.

    Data: uses useMeeting(meetingId) hook.
    RSVP: uses useRSVPMeeting mutation. Update optimistically.

    **MeetingNotesEditor.tsx:**
    Live notes during a meeting.
    Props: meetingId: string.

    Layout:
    - Tab bar: "Geteilte Notizen" / "Private Notizen"
    - Textarea for note input (auto-expanding, placeholder text based on tab)
    - "Speichern" button (saves note via useCreateNote)
    - List of existing notes below, sorted by created_at DESC
    - Each note shows: author name, timestamp, content, edit button (if author)
    - Private notes tab: only shows notes where is_private=true (already filtered by backend)

    Data: useMeetingNotes(meetingId) for listing, useCreateNote/useUpdateNote for mutations.

    This component is designed to be used inside the VideoCallView (as a side panel) or standalone from the meeting detail page. Accept an optional `compact` prop for in-call usage (reduced chrome).

    **MeetingActionItems.tsx:**
    Action items list for a meeting.
    Props: meetingId: string.

    Layout:
    - "Neuer Aktionspunkt" button at top
    - Inline create form (appears on button click): title input, assignee selector, due date picker, description textarea
    - List of action items as cards/rows:
      - Checkbox for completion (calls useCompleteActionItem)
      - Title (strikethrough if completed)
      - Assignee avatar + name
      - Due date with color coding (red if overdue, yellow if due today, gray if future)
      - Edit button (inline edit or dialog)

    Data: useMeetingActionItems(meetingId), useCreateActionItem, useUpdateActionItem, useCompleteActionItem.

    Action items with `assigned_to` show the assignee. Items without assignee show "Nicht zugewiesen" in gray.

    **MeetingSummary.tsx:**
    Post-meeting summary view (shown for completed meetings).
    Props: meetingId: string.

    Layout (card-based summary):
    - **Meeting Info Card:**
      - Title, date, duration (actual_end - actual_start), organizer
      - Status badge: "Abgeschlossen"
      - Attendees who actually participated (from call participants if available)

    - **Notes Section:**
      - Renders MeetingNotesEditor in read-only mode (shared notes only, no private notes of others)
      - Or renders a simplified list of shared notes

    - **Action Items Section:**
      - Renders MeetingActionItems component (still editable -- action items persist after meeting)
      - Summary line: "X von Y Aktionspunkte erledigt"

    - **Recording Section (if recording exists):**
      - Link to recording download/playback
      - Recording duration, file size
      - Data from useRecordings(callId) where callId = meeting.call_id

    - **CRM Link (if linked):**
      - "Verknuepft mit: {entity}" with click-through to CRM entity

    This is the MEET-04 "summary record" -- the meeting itself in completed status serves as the summary, with notes and action items attached.
  </action>
