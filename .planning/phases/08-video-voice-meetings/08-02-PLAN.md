  <action>
    Create `backend/internal/chat/reaction/` package following the exact same patterns as `backend/internal/chat/channel/` and `backend/internal/chat/message/`.

    **errors.go:**
    Define sentinel errors:
    - `ErrReactionNotFound` -- reaction does not exist
    - `ErrDuplicateReaction` -- user already reacted with this emoji on this message (catch unique constraint violation)
    - `ErrMessageNotFound` -- message does not exist (for validation)

    **repository.go:**
    Define `Repository` interface:
    ```go
    type Repository interface {
        CreateReaction(ctx context.Context, messageID, userID uuid.UUID, emoji string) (*models.MessageReaction, error)
        GetReaction(ctx context.Context, messageID, userID uuid.UUID, emoji string) (*models.MessageReaction, error)
        DeleteReaction(ctx context.Context, reactionID uuid.UUID) error
        ListReactionsByMessage(ctx context.Context, messageID uuid.UUID) ([]models.MessageReaction, error)
        ListReactionsByMessages(ctx context.Context, messageIDs []uuid.UUID) (map[uuid.UUID][]models.MessageReaction, error)
        CountReactionsByMessage(ctx context.Context, messageID uuid.UUID) (int, error)
    }
    ```
    Note: `ListReactionsByMessages` (plural) is a batch method for loading reactions for multiple messages at once (avoids N+1 when rendering a message list).

    **postgres_repository.go:**
    Implement `PostgresRepository` with `*pgxpool.Pool`.
    - `CreateReaction`: INSERT with ON CONFLICT DO NOTHING check. If 0 rows affected, return ErrDuplicateReaction.
    - `GetReaction`: SELECT WHERE message_id AND user_id AND emoji.
    - `DeleteReaction`: DELETE WHERE id. If 0 rows affected, return ErrReactionNotFound.
    - `ListReactionsByMessage`: SELECT WHERE message_id ORDER BY created_at ASC.
    - `ListReactionsByMessages`: SELECT WHERE message_id = ANY($1) ORDER BY message_id, created_at ASC. Group results into map by message_id in Go.
    - `CountReactionsByMessage`: SELECT COUNT(*) WHERE message_id.

    Use `pgx.Row.Scan` for single rows, `pgx.Rows` iteration for lists. Follow the exact scanning patterns from existing chat repositories.
  </action>

    - Repository interface has all 6 methods
    - PostgresRepository implements the Repository interface (compile check confirms)
  </verify>

  <name>Task 2: Reaction service with toggle semantics + unit tests</name>

  <action>
    **service.go:**
    Create `Service` struct with `Repository` dependency (constructor injection, same pattern as channel/message services).

    Methods:
    - `ToggleReaction(ctx, messageID, userID uuid.UUID, emoji string) (added bool, err error)`:
      1. Try `GetReaction` to check if user already reacted with this emoji
      2. If found -> `DeleteReaction` and return (added=false, nil)
      3. If not found (ErrReactionNotFound) -> `CreateReaction` and return (added=true, nil)
      4. Handle race conditions: if CreateReaction returns ErrDuplicateReaction (concurrent toggle), treat as already-exists and delete instead
      This is the research pattern from 08-RESEARCH.md Pattern 4.

    - `GetReactionSummaries(ctx, messageID, currentUserID uuid.UUID) ([]models.ReactionSummary, error)`:
      1. Call `ListReactionsByMessage`
      2. Group reactions by emoji
      3. For each emoji group: count, collect user IDs, check if currentUserID is in the set (me_reacted)
      4. Return sorted by first occurrence (order of first reaction per emoji)

    - `GetBulkReactionSummaries(ctx, messageIDs []uuid.UUID, currentUserID uuid.UUID) (map[uuid.UUID][]models.ReactionSummary, error)`:
      1. Call `ListReactionsByMessages` (batch)
      2. For each message, apply the same grouping logic as GetReactionSummaries
      3. Return map of messageID -> []ReactionSummary
      This is the optimized path for rendering message lists without N+1.

    Validate emoji input: must be non-empty, max 32 characters (matches DB column). Reject empty strings.

    **service_test.go:**
    Write unit tests using a mock repository (define `MockRepository` implementing the `Repository` interface in the test file).

    Test cases:
    - `TestToggleReaction_AddNew`: First reaction adds successfully, returns added=true
    - `TestToggleReaction_RemoveExisting`: Toggle same emoji again removes it, returns added=false
    - `TestToggleReaction_DifferentEmojis`: Same user can react with different emojis on same message
    - `TestToggleReaction_DifferentUsers`: Different users can use same emoji
    - `TestToggleReaction_EmptyEmoji`: Rejects empty emoji string with error
    - `TestGetReactionSummaries_Empty`: Returns empty slice for unreacted message
    - `TestGetReactionSummaries_MultipleEmojis`: Groups by emoji, counts correct, me_reacted correct
    - `TestGetReactionSummaries_MeReacted`: Current user's reaction flagged correctly
    - `TestGetBulkReactionSummaries_MultipleMessages`: Batch loading works, returns correct map

    Follow the exact test patterns from `backend/internal/chat/channel/service_test.go` or `backend/internal/chat/message/service_test.go`.
