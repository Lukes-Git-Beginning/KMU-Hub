**gRPC Server (`backend/internal/server/email_grpc.go`):**

Create `EmailGRPCServer` implementing the generated `emailv1.EmailServiceServer` interface. Follow the exact same pattern as `crm_grpc.go`. Constructor takes all service dependencies:

```go
func NewEmailGRPCServer(
    accountService *account.Service,
    messageService *message.Service,
    sendService *send.Service,
    signatureService *signature.Service,
    attachmentService *attachment.Service,
    syncEngine *sync.Engine,
) *EmailGRPCServer
```

Implement all ~35 RPCs. Each RPC follows thin-handler pattern:
1. Extract user_id from gRPC metadata (same pattern as crm_grpc.go: `metadata.FromIncomingContext`)
2. Parse request fields into service-layer inputs
3. Call appropriate service method
4. Convert result to proto response
5. Return response or gRPC status error

Key RPCs with specific behavior:
- `CreateEmailAccount` -- call accountService.Create, then syncEngine.StartWorker
- `DeleteEmailAccount` -- call syncEngine.StopWorker, then accountService.Delete
- `TestEmailConnection` -- call accountService.TestConnection
- `ListMessages` -- supports folder_id filter and search query (routes to messageService.ListByFolder or messageService.Search)
- `GetMessage` -- if body is empty in DB (lazy fetch), trigger on-demand IMAP fetch via sync engine, then return
- `SendEmail/ReplyEmail/ForwardEmail` -- call sendService.Send/Reply/Forward
- `TriggerSync` -- call syncEngine.TriggerSync
- `GetSyncStatus` -- call syncEngine.GetStatus
- `SetReadFlag` -- call messageService.MarkRead/MarkUnread + push flag change to IMAP via sync engine
- `UploadAttachment` -- stream bytes to attachmentService.CreateFromStream, return minio_key
- `GetAttachmentDownloadURL` -- call attachmentService.GetDownloadURL, return presigned URL
