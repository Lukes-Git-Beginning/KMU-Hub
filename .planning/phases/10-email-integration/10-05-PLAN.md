**Sync Engine (`sync/engine.go` + `sync/worker.go`):**

Engine manages per-user sync workers:

```go
type Engine struct {
    accountService *account.Service
    messageService MessageSyncer // interface to avoid circular import
    attachmentStore AttachmentStorer
    workers        map[uuid.UUID]*Worker
    mu             sync.RWMutex
    logger         *slog.Logger
}
```

- `NewEngine(accountService, messageSyncer, attachmentStorer)` -- constructor
- `Start(ctx context.Context) error` -- loads all active accounts via accountService.ListActive(), starts a worker goroutine per account
- `Stop()` -- gracefully stops all workers
- `StartWorker(ctx, accountID)` -- starts sync for a specific account (called when new account created)
- `StopWorker(accountID)` -- stops sync for a specific account (called when account deleted)
- `TriggerSync(accountID)` -- forces immediate sync cycle (called from gRPC)
- `GetStatus(accountID) *SyncStatus` -- returns last_sync, is_syncing, error

Worker runs per-user sync loop:

```go
type Worker struct {
    account     *models.EmailAccount
    imap        *IMAPClient
    msgSyncer   MessageSyncer
    attachStore AttachmentStorer
    triggerCh   chan struct{}
    logger      *slog.Logger
}
```

Worker.Run(ctx) lifecycle:
1. Connect to IMAP server using decrypted credentials
2. List all IMAP folders, sync to DB (create/update email_folders)
3. For each folder: check UIDVALIDITY against stored value
   - If changed: wipe local messages for that folder, re-sync from scratch, log warning
   - If same: delta sync -- fetch UIDs > highest_uid stored locally
4. For INBOX: enter IDLE loop if supported, else poll every 60 seconds
5. For non-INBOX folders: poll every 5 minutes
6. On new messages from IDLE/poll: fetch headers + preview, store in DB
7. On trigger (from triggerCh): force immediate sync cycle
8. Reconnection: exponential backoff (1s, 2s, 4s, 8s, max 60s) on connection failure

Initial sync depth: fetch last 30 days of headers on first sync. Full body fetched on-demand when user opens a message (via GetMessage RPC).

IDLE restart: every 25 minutes (per RFC 2177 recommendation). go-imap v2 `IdleCommand` with `Close()` after timer.

Delta sync for new messages:
```go
// Fetch UIDs newer than highest_uid
uidSet := imap.UIDSetNum()
uidSet.AddRange(imap.UID(highestUID+1), imap.UIDSetMax)
```

Folder type detection: map well-known folder names to types:
- INBOX -> inbox
- Sent/Sent Items/Sent Messages/Gesendet -> sent
- Drafts/Entwürfe -> drafts
- Trash/Deleted/Papierkorb/Deleted Items -> trash
- Spam/Junk -> spam
- Archive/Archiv -> archive
- Everything else -> custom

Read/unread flag sync (IMAP -> Hub): during delta sync, check \Seen flag on fetched messages. Store as is_read in DB.

**Thread Reconstruction (`message/thread.go`):**

```go
func (s *Service) AssignThread(ctx context.Context, msg *models.EmailMessage) error
```

Thread assignment logic:
1. Check `msg.InReplyTo` -- look up message with matching message_id header
2. If found, use that message's thread_id
3. If not found, check `msg.References` array (last element first) -- look up any message with matching message_id header
4. If found, use that message's thread_id
5. If still not found, this is a new conversation -- generate new thread_id (uuid.New())
6. Update msg.ThreadID in DB

For batch thread reconstruction (initial sync or UIDVALIDITY reset), use the gatherstars-com/jwz library:
```go
func (s *Service) ReconstructThreads(ctx context.Context, messages []*models.EmailMessage) error
```
This builds a full thread tree from message headers and assigns consistent thread IDs. Uses `jwz.NewThreader()` with `jwz.MessageIDFromHeader` interface adapter.

Subject-based fallback: if a message has no References or In-Reply-To (broken client), attempt to match by normalized subject (strip Re:/Fwd:/AW:/WG: prefixes, case-insensitive) + overlapping sender/recipient within a 7-day window. Only use as fallback.

Unit tests: test thread assignment with various header combinations, test subject fallback, test UIDVALIDITY reset.

Send flow:
1. Get decrypted SMTP credentials from account service
2. Build MIME message via MIMEBuilder
3. Append user's signature HTML if signature_id provided
4. Connect to SMTP server (port 587 STARTTLS via `smtp.SendMail`, port 465 TLS via `smtp.SendMailTLS`)
5. Send email
6. Save copy to local DB with folder_type=sent
7. Set proper threading headers for replies:
   - In-Reply-To: original message's Message-ID
   - References: original message's References + original message's Message-ID
8. Return saved message model

**MIME Builder (`send/mime_builder.go`):**

Use `go-message` to construct proper MIME messages:
```go
type MIMEBuilder struct{}

func (b *MIMEBuilder) Build(input MIMEInput) (io.Reader, error)
```

MIMEInput: From, To, CC, BCC ([]EmailAddress), Subject, BodyHTML, BodyText, Attachments ([]AttachmentData), InReplyTo, References, MessageID.

Build logic:
- Generate Message-ID: `<uuid@kmuhub>` format
- Set Date header (RFC 5322 format)
- If has attachments: create `multipart/mixed` top-level
  - First part: `multipart/alternative` with text/plain + text/html
  - Subsequent parts: each attachment as MIME part with Content-Disposition: attachment
- If inline images exist (Content-ID set): use `multipart/related` for HTML + inline images
- If no attachments: `multipart/alternative` with text/plain + text/html
- Use `go-message`'s `mail.CreateWriter` for proper header encoding (RFC 2047 for non-ASCII)

For forwarding: include original message attachments. Fetch from MinIO via attachment store, add as new MIME parts.

Unit tests: test MIME construction for plain, HTML, with attachments, reply headers, forward with attachments.
