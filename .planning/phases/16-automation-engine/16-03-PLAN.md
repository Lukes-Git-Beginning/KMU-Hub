    **2. Create TypeScript types** at `desktop/src/renderer/src/api/automation-types.ts`:
    - `Automation` interface: id, name, description, scope ('personal'|'team'|'organization'), owner_id, trigger_type, trigger_config (Record<string,any>), conditions (ConditionConfig), actions (ActionConfig[]), is_active, max_steps, template_id, last_triggered_at, created_at, updated_at
    - `AutomationExecution` interface: id, automation_id, chain_id, trigger_event (Record<string,any>), condition_result, status ('running'|'completed'|'failed'|'skipped'|'aborted'), steps (ExecutionStep[]), error_message, started_at, completed_at, duration_ms
    - `ExecutionStep` interface: action_type, input (Record<string,any>), output (Record<string,any>), error, duration_ms
    - `AutomationTemplate` interface: id, name, description, category ('vertrieb'|'personal'|'finanzen'|'kommunikation'), complexity ('einfach'|'mittel'|'fortgeschritten'), trigger_type, trigger_config, conditions, actions
    - `TriggerDefinition` interface: type, module, name, description, event_type, fields (TriggerField[]), config_params (ConfigParam[])
    - `TriggerField` interface: key, label, type ('string'|'number'|'boolean'|'date'), operators (string[])
    - `ActionDefinition` interface: type, module, name, description, params (ConfigParam[]), output_fields (OutputField[])
    - `ConfigParam` interface: key, label, type, required, default_value
    - `OutputField` interface: key, label, type
    - `ConditionConfig` interface: mode ('simple'|'expression'), simple (SimpleCondition|null), expression (string)
    - `SimpleCondition` interface: and (SimpleCondition[]), or (SimpleCondition[]), field, operator, value
    - `ActionConfig` interface: type, config (Record<string,any>), on_error ('continue'|'abort')
    - `AutomationStats` interface: total, active, inactive, total_executions, successful, failed, success_rate

    **3. Create API client** at `desktop/src/renderer/src/api/automation-client.ts`:
    - Follow the pattern from calendar-client.ts / video-client.ts (fetch wrapper, not openapi-fetch)
    - Functions matching all gateway endpoints:
      - createAutomation(data), updateAutomation(id, data), deleteAutomation(id)
      - getAutomation(id), listAutomations(params?)
      - enableAutomation(id), disableAutomation(id)
      - listExecutions(automationId, params?), getExecution(executionId)
      - listTriggerDefinitions(), listActionDefinitions()
      - listTemplates(category?), createFromTemplate(templateId, data)
      - testCondition(data), dryRunAutomation(data)
      - getAutomationStats()
    - All functions use the existing `request()` helper from api-client.ts
    - Error handling consistent with other API clients

    **4. Create TanStack Query hooks** at `desktop/src/renderer/src/api/hooks/useAutomation.ts`:
    - Query hooks:
      - `useAutomations(params?)` -- list with filter, staleTime 30s
      - `useAutomation(id)` -- single automation detail
      - `useAutomationExecutions(automationId, params?)` -- execution log
      - `useAutomationExecution(executionId)` -- single execution detail
      - `useTriggerDefinitions()` -- trigger catalog, staleTime 5min (rarely changes)
      - `useActionDefinitions()` -- action catalog, staleTime 5min
      - `useAutomationTemplates(category?)` -- template list, staleTime 5min
      - `useAutomationStats()` -- statistics, staleTime 60s
    - Mutation hooks:
      - `useCreateAutomation()` -- invalidates automations list
      - `useUpdateAutomation()` -- invalidates automations list + detail
      - `useDeleteAutomation()` -- invalidates automations list
      - `useEnableAutomation()` -- optimistic update of is_active
      - `useDisableAutomation()` -- optimistic update of is_active
      - `useCreateFromTemplate()` -- invalidates automations list
      - `useTestCondition()` -- no cache (always fresh)
      - `useDryRunAutomation()` -- no cache (always fresh)
    - Query keys: ['automations', ...params] pattern consistent with other modules

    **5. Create Zustand store** at `desktop/src/renderer/src/stores/automatisierung.ts`:
    - UI-only state (no persist -- all server data via TanStack Query):
      - wizardStep: number (0-3 for Trigger, Condition, Actions, Review)
      - editorMode: 'wizard' | 'editor' (toggle between wizard and react-flow)
      - draftWorkflow: Partial<Automation> | null (the workflow being created/edited)
      - selectedAutomationId: string | null
      - templateGrouping: 'module' | 'complexity'
      - executionLogFilter: { status?: string, dateRange?: [Date, Date] }
    - Actions:
      - setWizardStep, nextStep, prevStep
      - setEditorMode (toggle between wizard and editor)
      - setDraftWorkflow, updateDraftTrigger, updateDraftConditions, addDraftAction, removeDraftAction, updateDraftAction
      - selectAutomation, clearSelection
      - setTemplateGrouping, setExecutionLogFilter
      - resetDraft (clear wizard state for new automation)
      - loadAutomationIntoDraft (populate draft from existing automation for editing)
    - The draft workflow is the SINGLE SOURCE OF TRUTH for both wizard and editor views
