    **4. Create workflow engine** at `backend/internal/automation/engine/engine.go`:
    - `WorkflowEngine` struct with condEvaluator (*condition.Evaluator), actionRegistry (*action.ActionRegistry), logger (*ExecutionLogger), semaphore (chan struct{} of size 20)
    - `NewWorkflowEngine(evaluator, registry, logger) *WorkflowEngine`
    - `Execute(ctx context.Context, auto models.Automation, evt models.EventPayload) error`:
      1. Acquire semaphore slot (or return if full)
      2. Create execution ID (uuid.New()), start timer
      3. Build initial environment from event payload (BuildEnvFromEvent)
      4. Log execution start
      5. Evaluate conditions via condEvaluator.Evaluate
      6. If condition false: log skipped, return nil
      7. For each action (up to auto.MaxSteps):
         - Get executor from registry
         - Execute with 10-second per-action timeout
         - Log action result (success or failure)
         - If error and OnError == "abort": break
         - Chain output: merge result.Output into env as `prev_*` and `step_N_*`
      8. Log execution complete with duration
    - Loop prevention: skip events where module_id == "automation"
    - Circuit breaker: track executions per automation per hour, auto-disable if > 100/hour

    **5. Create automation consumer** at `backend/internal/automation/engine/consumer.go`:
    - `AutomationConsumer` struct with matcher (*trigger.TriggerMatcher), engine (*WorkflowEngine)
    - `NewAutomationConsumer(matcher, engine) *AutomationConsumer`
    - `HandleEvent(ctx context.Context, evt models.EventPayload) error`:
      1. Skip if `evt.ModuleID == "automation"` (loop prevention)
      2. Find matching automations via matcher
      3. For each match, execute in goroutine with 30s timeout
      4. Return nil (non-blocking, errors logged in execution logs)

    **6. Create execution logger** at `backend/internal/automation/engine/logger.go`:
    - `ExecutionLogger` struct with execRepo (workflow.ExecutionRepository)
    - `LogStart(ctx, execID, automationID, chainID, evt)`: insert execution with status "running"
    - `LogConditionSkipped(ctx, execID)`: update status "skipped"
    - `LogConditionError(ctx, execID, err)`: update status "failed"
    - `LogActionResult(ctx, execID, stepIndex, actionType, result, err)`: append to steps JSONB array
    - `LogComplete(ctx, execID, duration)`: update status "completed", set duration_ms
    - `LogStepLimitReached(ctx, execID, limit)`: update status "aborted"
    - All log methods are fire-and-forget (log error internally, never return error to caller)

    **7. Add event type constants** to `backend/internal/notification/event/types.go`:
