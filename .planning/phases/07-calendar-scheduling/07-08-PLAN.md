**CalendarSidebar.tsx:**
The main sidebar component (280px fixed width, collapsible per research recommendation).

Layout from top to bottom:
1. **Date navigation header** (~60px):
   - Current month/year label (e.g., "Februar 2026")
   - Left/right arrows to navigate months in the sidebar context
   - Small mini-calendar? NO -- per user decision, sidebar is a day agenda, NOT a mini month calendar

2. **Day agenda** (flexible height, scrollable):
   - Shows events for the selected date (from useCalendarStore.selectedDate, default = today)
   - Fetch events via useEventsInRange for the selected date (start = dayStart, end = dayEnd)
   - Display events chronologically using EventCard components (compact mode)
   - All-day events shown at top, then timed events sorted by start_time
   - If no events: "Keine Termine" placeholder
   - Updates when user clicks a date in the main calendar view (via store.setSelectedDate)
   - Show the date header: "Heute" or "Montag, 10. Feb." format

3. **Calendar list** (flexible height, collapsible groups):
   - CalendarListSidebar component (see below)

4. **Actions**:
   - "+ Neuer Kalender" button at bottom (opens CalendarSettingsDialog)
   - "Kalender durchsuchen" link (opens CalendarBrowsePage)

Toggle sidebar visibility: collapse button (ChevronLeft icon when open, ChevronRight when collapsed). Dispatches to useCalendarStore.toggleSidebar.

**calendars/CalendarListSidebar.tsx:**
Calendar list with grouped sections and visibility toggles.

Uses useCalendars() hook to get user's calendars.

Groups:
- **Meine Kalender** (calendar_type = 'personal' AND owner_id = currentUser)
- **Geteilte Kalender** (calendar_type = 'shared')
- **Andere** (subscribed calendars where user is not owner)

Each group:
- Collapsible section header (click to expand/collapse)
- List of calendars, each showing:
  - Checkbox (colored with calendar's display color) - toggles visibility in store
  - Calendar name
  - Three-dot menu (on hover): "Einstellungen", "Farbe aendern", "Abmelden" (for subscribed)

Checkbox color: Use the calendar's color or the user's color override (from CalendarWithMemberInfo.color_override || calendar.color).

On first load, if visibleCalendarIds in store is empty, auto-populate with all user's calendar IDs (all visible by default).

Toggling a checkbox calls useCalendarStore.toggleCalendarVisibility(calendarId). This immediately affects which events are shown in the calendar views (views filter by visibleCalendarIds).

Also sync visibility to server: call API to update calendar_members.is_visible (debounced, 1 second) so the setting persists across sessions.

```tsx
        </div>
      </div>

  );
}
```
