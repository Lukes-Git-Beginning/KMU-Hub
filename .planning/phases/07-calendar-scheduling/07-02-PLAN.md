Create TanStack Query hooks following the exact pattern from `useProjects.ts` and `useTasks.ts` (useQuery/useMutation with apiClient, proper query key conventions, invalidation on mutations).

**api/hooks/useCalendars.ts:**
- `useCalendars()` - list user's calendars (personal + subscribed)
- `useBrowsableCalendars()` - list shared calendars available to subscribe
- `useCalendarMembers(calendarId)` - list members of a calendar
- `useCreateCalendar()` - mutation
- `useUpdateCalendar()` - mutation with invalidation
- `useDeleteCalendar()` - mutation with invalidation
- `useAddCalendarMember()` - mutation
- `useRemoveCalendarMember()` - mutation
- `useSubscribeToCalendar()` - mutation
- `useUnsubscribeFromCalendar()` - mutation
- `useCalendarPreferences()` - query
- `useUpdateCalendarPreferences()` - mutation
- `useEventCategories()` - query (user's categories)
- `useCreateEventCategory()` - mutation
- `useDeleteEventCategory()` - mutation
- Query keys: ['calendars'], ['calendars', 'browsable'], ['calendars', id, 'members'], ['calendar-preferences'], ['event-categories']
- API endpoints: /api/v1/calendars, /api/v1/calendars/browse, /api/v1/calendars/:id/members, /api/v1/calendars/preferences, /api/v1/calendars/categories

**api/hooks/useEvents.ts:**
- `useEventsInRange(calendarIds, start, end)` - main calendar view query. Enabled only when calendarIds.length > 0. Returns ExpandedEvent[].
- `useEvent(eventId)` - single event detail
- `useEventAttendees(eventId)` - attendees list
- `useCreateEvent()` - mutation, invalidates events range queries
- `useUpdateEvent()` - mutation
- `useUpdateRecurringEvent()` - mutation (sends scope + original_date)
- `useDeleteEvent()` - mutation
- `useRSVPToEvent()` - mutation (eventId, status)
- `useSetEventReminders()` - mutation (eventId, minutes_before[])
- `useTaskDeadlines(start, end)` - query for task deadline overlay (calls existing work/tasks endpoint with date filter, or a dedicated endpoint if available)
- Query keys: ['events', { calendars: calendarIds, start, end }], ['events', id], ['events', id, 'attendees'], ['task-deadlines', { start, end }]
- API endpoints: /api/v1/calendar/events (with query params), /api/v1/calendar/events/:id, /api/v1/calendar/events/:id/attendees, /api/v1/calendar/events/:id/rsvp, /api/v1/calendar/events/:id/reminders

**api/hooks/useResources.ts:**
- `useResources(filters?)` - list resources (optional type/capacity/tag filters)
- `useResource(resourceId)` - single resource detail
- `useResourceAvailability(resourceId, date)` - bookings for a resource on a day
- `useCreateResource()` - mutation
- `useUpdateResource()` - mutation
- `useDeleteResource()` - mutation
- `useBookResource()` - mutation
- `useCancelBooking()` - mutation
- Query keys: ['resources'], ['resources', id], ['resources', id, 'availability', date]
- API endpoints: /api/v1/calendar/resources, /api/v1/calendar/resources/:id, /api/v1/calendar/resources/:id/availability, /api/v1/calendar/resources/bookings

**api/hooks/useHolidays.ts:**
- `useHolidays(year, countryCode, subdivisionCode?)` - query holidays for a year/country
- `useSeedHolidays()` - admin mutation to trigger Nager.Date fetch
- Query keys: ['holidays', { year, country, subdivision }]
- API endpoints: /api/v1/calendar/holidays, /api/v1/calendar/holidays/seed

**stores/calendar.ts (Zustand store):**
```typescript
import { create } from 'zustand';
import { persist } from 'zustand/middleware';

type CalendarView = 'day' | 'week' | 'month';

interface CalendarState {
  // View state
  currentView: CalendarView;
  currentDate: Date;
  selectedDate: Date; // for sidebar day agenda

  // Sidebar
  sidebarOpen: boolean;

  // Calendar visibility (which calendars are toggled on)
  visibleCalendarIds: Set<string>;

  // Task deadline layer
  showTaskDeadlines: boolean;

  // Actions
  setCurrentView: (view: CalendarView) => void;
  setCurrentDate: (date: Date) => void;
  setSelectedDate: (date: Date) => void;
  goToToday: () => void;
  navigateForward: () => void;
  navigateBackward: () => void;
  toggleSidebar: () => void;
  toggleCalendarVisibility: (calendarId: string) => void;
  setCalendarVisible: (calendarId: string, visible: boolean) => void;
  toggleTaskDeadlines: () => void;
}
```

Use zustand persist middleware with localStorage for view preferences (currentView, sidebarOpen, showTaskDeadlines). The currentDate and selectedDate should NOT be persisted (always start at today). Navigation methods (navigateForward/Backward) should use date-fns addDays/addWeeks/addMonths based on currentView.

Serialize visibleCalendarIds as an array in localStorage (Set is not JSON-serializable). Default visibleCalendarIds to empty set (populated on first calendar load).
