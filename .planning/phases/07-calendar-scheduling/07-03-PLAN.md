**postgres_repository.go:**
Implement all Repository methods using pgx. Key patterns:
- ListByUser: JOIN calendars with calendar_members WHERE user_id = $1 OR owner_id = $1, return CalendarWithMemberInfo with permission/color_override/is_visible
- ListBrowsable: SELECT shared calendars WHERE user NOT in calendar_members and user is NOT owner
- Subscribe: INSERT into calendar_members with permission='view', is_visible=true
- EnsurePersonalCalendar: SELECT WHERE owner_id=$1 AND is_default=true AND calendar_type='personal'. If not found, INSERT and return. Use ON CONFLICT for idempotency.
- Category UNIQUE constraint: catch pgx unique violation error for duplicate category names

```go
// ExpandRecurrence expands an RRULE string into concrete dates within a time window.
// dtstart is the original event start time. Returns dates in the event's timezone.
func ExpandRecurrence(rruleStr string, dtstart time.Time, windowStart, windowEnd time.Time) ([]time.Time, error)

// ValidateRRule checks if an RRULE string is valid RFC 5545.
func ValidateRRule(rruleStr string) error

// SetUntil modifies an RRULE string to add/replace the UNTIL parameter.
// Used for "this and future events" split.
func SetUntil(rruleStr string, until time.Time) (string, error)

// RemoveUntil removes the UNTIL parameter from an RRULE string.
// Returns the modified RRULE string.
func RemoveUntil(rruleStr string) (string, error)
```

Use `rrule.StrToRRule()` for parsing, `.DTStart()` to set start, `.Between()` for expansion. Handle timezone-aware expansion by loading the event's timezone via time.LoadLocation().

**postgres_repository.go:**
Implement all methods. Key patterns:
- ListInRange: Use the efficient SQL query from RESEARCH.md -- single query with calendar JOIN, LEFT JOIN on categories/resources, subquery for attendee_count and my_rsvp. Filter non-recurring by time range overlap, recurring by start_time < end AND (recurrence_end IS NULL OR recurrence_end > start).
- ListRecurringOverlapping: Return raw recurring events for service-layer RRULE expansion.
- SetReminders: DELETE all existing + INSERT new (within transaction).
- ListTaskDeadlinesInRange: SELECT from tasks WHERE due_date BETWEEN start AND end AND (assignee_id = userID OR userID is member of project). Return TaskDeadlineStub with project key via JOIN.
- ListUpcomingReminders: Complex query joining event_reminders with calendar_events, computing fire_time = start_time - interval 'N minutes', returning where fire_time BETWEEN windowStart AND windowEnd. For recurring events, the service layer handles expansion.

**service.go:**
Constructor takes Repository, CalendarRepository (for permission checks), and optional EventEmitter.

Key methods:
- `Create(ctx, actorID, req)` - validates title, time range, RRULE (if present). If has_video_call, generates LiveKit room name (cal-{eventID[:8]}). Adds creator as attendee with 'accepted'. Adds additional attendees as 'pending'. Sets default reminders from user preferences. Emits calendar.event.created + calendar.event.invited for each attendee.
- `ListEventsInRange(ctx, calendarIDs, start, end, userID)` - fetch non-recurring + recurring events. For recurring: expand RRULE, fetch exceptions, apply exceptions (skip cancelled, merge modified). Also include events where user is an attendee (even if calendar not in calendarIDs). Return sorted by start_time.
- `UpdateEvent(ctx, eventID, actorID, changes)` - for non-recurring events, direct update. Emits calendar.event.updated.
- `UpdateRecurringEvent(ctx, eventID, actorID, scope, originalDate, changes)` - three-way edit:
  - "this": Create exception with modified fields for originalDate. Do NOT modify master event.
  - "this_and_future": Set UNTIL on original RRULE to day before originalDate. Create new event with changed properties and RRULE starting from originalDate. Move exceptions on/after originalDate to new event. Move attendee records to new event. Must be a single transaction.
  - "all": Update master event directly. Clear exceptions that conflict with new RRULE (warn: this is destructive).
  Emit calendar.event.updated.
- `DeleteEvent(ctx, eventID, actorID)` - only creator can delete. For recurring, delete also deletes all exceptions. Emits calendar.event.cancelled.
- `RSVPToEvent(ctx, eventID, userID, status)` - validate status, update RSVP. Emit calendar.event.rsvp_changed.
- `SetReminders(ctx, eventID, actorID, minutesBefore)` - validate max 3 reminders, all > 0 minutes. Replace existing.
- `ListTaskDeadlinesInRange(ctx, userID, start, end)` - pass through to repo.
