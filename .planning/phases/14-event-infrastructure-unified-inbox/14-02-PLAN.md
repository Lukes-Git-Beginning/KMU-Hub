    **1. ChannelAdapter Interface** (`backend/internal/inbox/adapter/adapter.go`):

    Define the core adapter interface:
    ```go
    type ChannelAdapter interface {
        Channel() string  // "email", "chat", "notification"
        FetchNewMessages(ctx context.Context, userID uuid.UUID, since time.Time) ([]models.InboxMessage, error)
        HandleReply(ctx context.Context, messageID uuid.UUID, userID uuid.UUID, body string) error
        MarkReadOnSource(ctx context.Context, sourceID string, userID uuid.UUID) error
    }
    ```

    Also define `AdapterRegistry` struct that holds a map[string]ChannelAdapter for looking up adapters by channel name. Methods: `Register(adapter ChannelAdapter)`, `Get(channel string) (ChannelAdapter, bool)`, `All() []ChannelAdapter`.

    **2. EmailAdapter** (`backend/internal/inbox/adapter/email_adapter.go`):

    Implements ChannelAdapter for email messages.
    - `Channel()` returns "email"
    - `FetchNewMessages`: Creates InboxMessage from email data. For now, this is a stub that will be wired to the email gRPC service when the inbox consumer is registered. The adapter holds an email gRPC client interface (defined locally to avoid import cycles): `EmailClient interface { ListMessages(ctx, req) (resp, error) }`. If the client is nil, return empty slice (graceful degradation).
    - Normalization: sender_name from email From header, sender_email from email address, subject from email subject, preview from first 200 chars of body, deep_link as `/mails/{message_id}`, source_id = email thread_id (one inbox item per thread per research recommendation)
    - `HandleReply`: Calls email service SendMessage RPC via gRPC client
    - `MarkReadOnSource`: Calls email service MarkRead RPC via gRPC client

    **3. ChatAdapter** (`backend/internal/inbox/adapter/chat_adapter.go`):

    Implements ChannelAdapter for Chat DMs and @mentions only (not regular channel messages, per research and context decisions).
    - `Channel()` returns "chat"
    - `FetchNewMessages`: Creates InboxMessage from chat DM/mention data. Holds a ChatClient interface. If nil, return empty slice.
    - Normalization: sender_name from user display name, sender_id from message author, subject = channel name or "Direktnachricht", preview from first 200 chars, deep_link as `/chat/{channel_id}`, source_id = message_id
    - `HandleReply`: Calls chat service CreateMessage RPC
    - `MarkReadOnSource`: Calls chat service MarkRead RPC

    **4. NotificationAdapter** (`backend/internal/inbox/adapter/notification_adapter.go`):

    Implements ChannelAdapter for system notifications.
    - `Channel()` returns "notification"
    - `FetchNewMessages`: Creates InboxMessage from notification data. Holds a NotificationClient interface.
    - Normalization: sender_name = "System" or module name, subject from notification title, preview from notification body, deep_link from notification deep_link, source_id = notification_id
    - `HandleReply`: Notifications are not replyable in most cases. Return nil for non-actionable notifications. For actionable ones (e.g., leave approval), route to the appropriate module via deep_link.
    - `MarkReadOnSource`: Calls notification service MarkRead RPC

    **6. Message Service** (`backend/internal/inbox/message/service.go`):

    Service struct holds: repo Repository, adapters *adapter.AdapterRegistry, pool *pgxpool.Pool (for snooze worker).

    Methods map 1:1 to repository but add business logic:
    - `Create`: Check for duplicate via GetBySourceID before inserting. If duplicate exists, update preview/subject if newer.
    - `MarkRead`: Also call adapter.MarkReadOnSource to sync back to originating system.
    - `Reply`: Look up the message, get its channel, find the adapter, call HandleReply. Return error if adapter not found.
    - `Snooze`: Validate snooze_until is in the future. Set is_read=false on unsnooze so item reappears as unread.
    - `AssignMessage`: Delegate to repo. Return "already assigned" error if repo returns false.
    - `GetUnreadCounts`: Simple passthrough to repo.

    `StartSnoozeWorker(ctx context.Context, interval time.Duration)`: Background goroutine that polls every 60 seconds for expired snoozed items (snoozed_until <= NOW()). On unsnooze, emit an event via pg_notify('notification_delivery', ...) so gateway can push a WebSocket update to the user.

    **4. Condition Evaluator** (`backend/internal/inbox/routing/evaluator.go`):

    This is the reusable AND/OR condition tree evaluator designed for Phase 16 Automation reuse.

    Use the `models.Condition` struct from models/inbox.go. Implement `Evaluate(msg *models.InboxMessage) bool`:

    - If `c.And` is non-empty: ALL sub-conditions must evaluate to true (short-circuit on first false)
    - If `c.Or` is non-empty: ANY sub-condition must evaluate to true (short-circuit on first true)
    - If neither And nor Or: evaluate as leaf condition using `evaluateLeaf(msg)`

    `evaluateLeaf` extracts the field value from the message by field name:
    - "channel" -> msg.Channel
    - "sender" / "sender_name" -> msg.SenderName
    - "sender_email" -> msg.SenderEmail (deref pointer, empty string if nil)
    - "subject" -> msg.Subject
    - "preview" / "body" -> msg.Preview (we only match against preview, not full body per research)
    - "tags" -> strings.Join(msg.Tags, ",") for contains/in operators
    - "crm_linked" -> "true" if msg.CRMContactID != nil, else "false"
    - "team_inbox" -> msg.TeamInboxID.String() if not nil, else ""

    Operators:
    - "equals": case-insensitive string equality
    - "not_equals": case-insensitive inequality
    - "contains": case-insensitive substring match (strings.Contains after ToLower)
    - "not_contains": negation of contains
    - "starts_with": case-insensitive prefix match
    - "ends_with": case-insensitive suffix match
    - "in": value is comma-separated list, field value must be one of them
    - "not_in": negation of in
    - "exists": field value is non-empty
    - "not_exists": field value is empty

    Value from the Condition struct is always converted to string for comparison.

    **5. Condition Evaluator Tests** (`backend/internal/inbox/routing/evaluator_test.go`):

    Write comprehensive tests:
    - TestEvaluateLeaf_Equals: exact match, case insensitivity
    - TestEvaluateLeaf_Contains: substring match
    - TestEvaluateLeaf_StartsWith / EndsWith
    - TestEvaluateLeaf_In / NotIn: comma-separated value lists
    - TestEvaluateLeaf_Exists / NotExists: empty vs non-empty fields
    - TestEvaluateAnd: all true -> true, one false -> false, empty And -> true
    - TestEvaluateOr: one true -> true, all false -> false, empty Or -> false

    **7. Routing Service** (`backend/internal/inbox/routing/service.go`):

    Service struct holds: repo Repository, teamService team.Service (for routing actions), messageRepo message.Repository (for tag updates), emailClient (interface for auto-reply).

    Key methods:
    - `EvaluateAndApply(ctx, msg *models.InboxMessage) error`: Load all active rules (cache with 60s TTL for performance). Evaluate rules in priority order. On first match, execute all actions. Stop after first matching rule (first-match-wins).
    - `TestRule(ctx, conditions models.Condition, msg *models.InboxMessage) bool`: Test whether conditions match a message (for the TestRoutingRule RPC).
    - `executeActions(ctx, msg *models.InboxMessage, actions []models.Action) error`: For each action:
      - "route_to_team": Set msg.TeamInboxID from action config, update via messageRepo
      - "assign_to": Set msg.AssignedTo from action config, update via messageRepo
      - "add_tags": Append tags to msg.Tags, update via messageRepo
      - "auto_reply": Call emailClient.Send() with auto-reply body from config (only for email channel). Log warning if channel is not email.

    - `cachedRules` field with sync.RWMutex and lastRefresh time.Time for 60s rule cache.
    - `refreshCache(ctx)`: Reload rules from DB if cache is stale.
