    **1. InboxService gRPC Server** (`backend/internal/server/inbox_grpc.go`):

    Create the gRPC server implementation following the exact pattern from `notification_grpc.go` and other `*_grpc.go` files in the server package.

    Struct:
    ```go
    type InboxGRPCServer struct {
        inboxv1.UnimplementedInboxServiceServer
        messageService *message.Service
        teamService    *team.Service
        routingService *routing.Service
    }
    ```

    Constructor: `NewInboxGRPCServer(messageSvc, teamSvc, routingSvc) *InboxGRPCServer`

    Implement all 27 RPCs. Each handler follows the thin-handler pattern:
    1. Extract fields from protobuf request
    2. Convert to domain types (uuid.UUID from string, time.Time from Timestamp)
    3. Call appropriate service method
    4. Convert domain result to protobuf response
    5. Map domain errors to gRPC status codes

    Error mapping (use `mapInboxError` helper):
    - `message.ErrMessageNotFound` -> `codes.NotFound`
    - `message.ErrAlreadyAssigned` -> `codes.AlreadyExists`
    - `message.ErrInvalidSnoozeTime` -> `codes.InvalidArgument`
    - `message.ErrAdapterNotFound` -> `codes.Unimplemented`
    - `team.ErrTeamInboxNotFound` -> `codes.NotFound`
    - `team.ErrNotTeamAdmin` -> `codes.PermissionDenied`
    - `team.ErrNotTeamMember` -> `codes.PermissionDenied`
    - `routing.ErrRuleNotFound` -> `codes.NotFound`
    - `routing.ErrInvalidConditions` -> `codes.InvalidArgument`
    - default -> `codes.Internal`

    Key RPC implementations:
    - `ListMessages`: Convert ListFilter from proto, call messageService.List, convert results
    - `ReplyToMessage`: Call messageService.Reply which routes through adapter
    - `SnoozeMessage`: Convert proto Timestamp to time.Time, call messageService.Snooze
    - `ClaimMessage`: Call teamService.ClaimMessage, handle ErrAlreadyAssigned
    - `TestRoutingRule`: Unmarshal conditions from proto Struct, create test InboxMessage from proto, call routingService.TestRule

    For user context: Extract user_id from gRPC metadata (the gateway sets x-user-id header which maps to gRPC metadata). Use `uuid.Parse()` to convert.

    **2. Inbox Event Consumer** (add to `backend/cmd/notification/main.go`):

    Create an `InboxConsumer` struct that sits between the EventBus and the inbox services. Register it as a handler on the EventBus alongside the existing notification ProcessEvent handler.

    ```go
    type InboxConsumer struct {
        messageService *message.Service
        routingService *routing.Service
        adapters       *adapter.AdapterRegistry
    }
    ```

    The consumer's `HandleEvent` method processes incoming events:
    1. Determine which channel adapter should handle this event based on event module:
       - "email" module -> EmailAdapter
       - "chat" module -> ChatAdapter
       - All other modules -> NotificationAdapter (generic notification items)
    2. Skip events with module_id="inbox" to prevent circular loops (per research pitfall #4)
    3. Create InboxMessage from event payload:
       - user_id from target_user_ids (create one inbox_message per target user)
       - channel from adapter.Channel()
       - source_id from event resource_id
       - sender_name from event actor info
       - subject from event title
       - preview from event body
       - deep_link from event deep_link
       - received_at from event timestamp
    4. For each target user, call messageService.Create (handles dedup internally)
    5. Apply routing rules: call routingService.EvaluateAndApply for each new message
    6. Emit pg_notify('notification_delivery', ...) for gateway WebSocket push

    Register the consumer:
    ```go
    inboxConsumer := &InboxConsumer{...}
    eventBus.RegisterHandler("*", inboxConsumer.HandleEvent)
    ```

    **3. Update notification binary main.go:**

    Extend the existing notification binary to co-host InboxService:
    - Initialize inbox repositories: message.NewPostgresRepository, team.NewPostgresRepository, routing.NewPostgresRepository
    - Initialize channel adapters: adapter.NewAdapterRegistry() with EmailAdapter, ChatAdapter, NotificationAdapter (pass nil gRPC clients for now -- they'll be connected when gateway establishes connections)
    - Initialize inbox services: message.NewService, team.NewService, routing.NewService
    - Create InboxGRPCServer and register on the same gRPC server: `inboxv1.RegisterInboxServiceServer(grpcServer, inboxGRPC)`
    - Create InboxConsumer and register on EventBus
    - Start snooze worker: `go messageService.StartSnoozeWorker(ctx, 60*time.Second)`
    - Add inbox imports to the import block

    The notification binary now serves both NotificationService and InboxService on the same gRPC port (:50054).

    **1. Inbox Gateway Routes** (`backend/internal/gateway/route_inbox.go`):

    Create `InboxRoutes` struct implementing the `RouteRegistrar` interface, following the exact pattern from `route_notification.go`, `route_biz.go`, `route_hr.go`.

    ```go
    type InboxRoutes struct {
        registry *ServiceRegistry
    }

    func NewInboxRoutes(registry *ServiceRegistry) *InboxRoutes {
        return &InboxRoutes{registry: registry}
    }

    func (ir *InboxRoutes) ServiceName() string { return "notification" }
    ```

    ServiceName returns "notification" because InboxService is co-hosted in the notification binary and shares the same gRPC connection.

    `RegisterRoutes` adds all HTTP endpoints under `/api/v1/inbox/`:

    **Message endpoints (auth required for all):**
    - `GET /api/v1/inbox/messages` -> ListMessages (query params: channel, is_read, is_starred, team_inbox_id, search, page_size, page_token)
    - `GET /api/v1/inbox/messages/{id}` -> GetMessage
    - `POST /api/v1/inbox/messages/{id}/read` -> MarkRead
    - `POST /api/v1/inbox/messages/{id}/unread` -> MarkUnread
    - `POST /api/v1/inbox/messages/{id}/star` -> ToggleStar
    - `POST /api/v1/inbox/messages/{id}/archive` -> ArchiveMessage
    - `POST /api/v1/inbox/messages/{id}/unarchive` -> UnarchiveMessage
    - `POST /api/v1/inbox/messages/{id}/snooze` -> SnoozeMessage (body: {snooze_until: timestamp})
    - `POST /api/v1/inbox/messages/{id}/unsnooze` -> UnsnoozeMessage
    - `POST /api/v1/inbox/messages/{id}/reply` -> ReplyToMessage (body: {body: string})
    - `POST /api/v1/inbox/messages/{id}/assign` -> AssignMessage (body: {assignee_id: string})
    - `GET /api/v1/inbox/unread-count` -> GetUnreadCount
    - `POST /api/v1/inbox/messages/bulk-read` -> BulkMarkRead (body: {ids: []string})
    - `POST /api/v1/inbox/messages/bulk-archive` -> BulkArchive (body: {ids: []string})

    **Team inbox endpoints (auth required, admin/manager for create/delete):**
    - `POST /api/v1/inbox/teams` -> CreateTeamInbox (RequirePermission "inbox", "manage_teams" or admin/manager role check)
    - `PUT /api/v1/inbox/teams/{id}` -> UpdateTeamInbox
    - `DELETE /api/v1/inbox/teams/{id}` -> DeleteTeamInbox
    - `GET /api/v1/inbox/teams` -> ListTeamInboxes
    - `POST /api/v1/inbox/teams/{id}/members` -> AddTeamMember
    - `DELETE /api/v1/inbox/teams/{id}/members/{user_id}` -> RemoveTeamMember
    - `GET /api/v1/inbox/teams/{id}/members` -> ListTeamMembers
    - `POST /api/v1/inbox/messages/{id}/claim` -> ClaimMessage

    **Routing rule endpoints (auth required, admin/manager):**
    - `POST /api/v1/inbox/rules` -> CreateRoutingRule
    - `PUT /api/v1/inbox/rules/{id}` -> UpdateRoutingRule
    - `DELETE /api/v1/inbox/rules/{id}` -> DeleteRoutingRule
    - `GET /api/v1/inbox/rules` -> ListRoutingRules
    - `POST /api/v1/inbox/rules/test` -> TestRoutingRule

    Each handler follows the gateway pattern:
    1. Parse request (path params, query params, JSON body)
    2. Get gRPC client via `ir.registry.GetConnection("notification")` then `inboxv1.NewInboxServiceClient(conn)`
    3. Build proto request
    4. Call gRPC method
    5. Map gRPC errors to HTTP status codes
    6. Respond with JSON

    Add `getInboxClient(r *http.Request) (inboxv1.InboxServiceClient, error)` helper method that gets the gRPC connection from the registry and creates a client. Cache the client on first use (same pattern as other route files).
