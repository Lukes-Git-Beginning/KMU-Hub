Build the notification service backend: event bus infrastructure, notification storage with smart grouping, and preference evaluation engine.

Purpose: This is the core notification engine that all current and future modules (Phases 4-13) will use to notify users. The event bus receives events from any service via PostgreSQL LISTEN/NOTIFY. This service runs as an independent microservice following the established pattern (auth, CRM, chat).

Output: Complete notification microservice internals (event bus, repositories, services, tests) plus protobuf definitions and database schema. The gRPC server and cmd/main.go entry point are included. Gateway integration (HTTP routes, WebSocket delivery) happens in Plan 03.

- `EventBus` struct with connString, handlers map, reconnectWait duration
- `EventHandler` type: `func(ctx context.Context, event models.EventPayload) error`
- `NewEventBus(connString string, opts ...BusOption) *EventBus` - with functional options for reconnect wait (default 5s)
- `RegisterHandler(eventType string, handler EventHandler)` - register handler for specific event type. Use `"*"` as wildcard for all events.
- `Listen(ctx context.Context) error` - outer reconnection loop. On context cancellation, returns nil. On connection error, logs warning and retries after reconnectWait.
- `listenLoop(ctx context.Context) error` - inner loop: connect to PostgreSQL with dedicated connection (not from pool), execute `LISTEN events`, loop on `conn.WaitForNotification(ctx)`, unmarshal JSON payload into `models.EventPayload`, dispatch to registered handlers.
- `dispatch(ctx context.Context, event models.EventPayload)` - finds handlers for event.Type and wildcard handlers, calls each. Log errors but do not stop processing.
- **CRITICAL**: NOTIFY payload limited to 8000 bytes. Events must contain only metadata (type, IDs, priority), NOT full entity data. The notification service fetches rich data (titles, bodies) from source services when needed.
- **CRITICAL**: NOTIFY is ephemeral. The events table provides durability. The bus also checks for unprocessed events on startup (catch-up mechanism) via a `ProcessBacklog(ctx context.Context, repo EventRepository)` method that queries `SELECT * FROM events WHERE processed = false ORDER BY created_at ASC` and dispatches each.

- `ProcessEvent(ctx context.Context, event models.EventPayload) error` - the main event handler:

  2. Determine target users (who should receive this notification). Logic depends on event type:

**preference/service.go** - Preference evaluation pipeline:
- `Service` struct with `repo Repository`, `registry *event.EventTypeRegistry`
- `Evaluate(ctx context.Context, userID uuid.UUID, event models.EventPayload) (*DeliveryDecision, error)` implementing the pipeline from RESEARCH.md:
  1. **Urgent bypass**: If event priority is "urgent", return deliver=true, inApp=true, desktopPush=true, sound="alert"
  2. **Resource muting**: Check `IsResourceMuted(userID, event.ModuleID, event.ResourceID)`. If muted, return deliver=false.
  3. **Event-type preference**: Check `GetEventTypePreference(userID, event.Type)`. If found, use it.
  4. **Module default fallback**: If no event-type pref, check `GetModuleDefault(userID, event.ModuleID)`. If found, use it.
  5. **System default fallback**: If no module default, use the event type's default settings from the registry.
  6. **Low priority override**: If event priority is "low", force desktopPush=false regardless of preferences.
  7. **Quiet hours check** (for normal priority only): Call `isInQuietHours(ctx, userID)`. If in quiet hours, force desktopPush=false.
  8. Return final `DeliveryDecision{Deliver, InApp, DesktopPush, Sound, Reason}`
- `isInQuietHours(ctx context.Context, userID uuid.UUID) (bool, error)`:
  - Fetch quiet hours config. If not configured or not enabled, return false.
  - Check manual DND first: if manual_dnd=true and (manual_dnd_until is null OR manual_dnd_until > now), return true.
  - Check scheduled: convert current UTC time to user's timezone (use `time.LoadLocation`). Check if current local time falls within start_time-end_time on current day_of_week. Handle overnight windows (start > end means crosses midnight).
- CRUD methods: `GetPreferences`, `UpdatePreference`, `MuteResource`, `UnmuteResource`, `ListMutedResources`, `GetQuietHours`, `UpdateQuietHours`, `ToggleManualDND`
