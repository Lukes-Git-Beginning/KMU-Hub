<objective>
Refactor the gateway from a monolithic handler pattern with eager gRPC connections into a modular, lazy-connecting architecture with per-service route handlers and graceful degradation.

Purpose: The current gateway (900+ line GatewayHandler in http.go, eager gRPC connections in main.go) crashes if any backend service is unavailable at startup, and adding new services requires modifying the monolithic handler. This refactoring is prerequisite for adding the notification service (Plan 02-03) and all future services (Phases 5-13). The gateway must scale to support 7+ backend services.

Output: Modular gateway with ServiceRegistry, per-service route files, lazy gRPC connections, and 503 graceful degradation per-service.
</objective>

  <action>
Create the gateway infrastructure package at `backend/internal/gateway/`.

**registry.go** - ServiceRegistry that manages lazy gRPC connections:
- `ServiceRegistry` struct with a `map[string]*ServiceConnection` (service name -> connection info)
- `ServiceConnection` struct: `conn *grpc.ClientConn`, `address string`, `mu sync.RWMutex`
- `NewServiceRegistry() *ServiceRegistry`
- `Register(name, address string)` - registers a service address without connecting
- `GetConnection(name string) (*grpc.ClientConn, error)` - returns cached connection or creates one lazily using `grpc.NewClient()` (which is already lazy/non-blocking). Double-checked locking pattern (read lock first, then write lock if nil). Returns error if service name not registered.
- `Close()` - closes all connections (for graceful shutdown)
- Note: `grpc.NewClient()` does NOT perform I/O on creation. The actual connection happens on first RPC call. If the backend service is down, the RPC call will fail with a gRPC error, not the `NewClient` call. This means "lazy" is essentially free.

**registry_test.go** - Unit tests:
- Test Register + GetConnection returns a non-nil connection
- Test GetConnection for unregistered service returns error
- Test double GetConnection returns same connection (caching)
- Test Close does not panic
- Use `grpc.NewClient("localhost:0", grpc.WithTransportCredentials(insecure.NewCredentials()))` for test connections (no real server needed since NewClient is lazy)

**route_registrar.go** - Interface definition:
```go
type RouteRegistrar interface {
    RegisterRoutes(r chi.Router, authMiddleware func(http.Handler) http.Handler)
    ServiceName() string
}
```
This is the contract each per-service route module implements.

**helpers.go** - Shared helper functions extracted from http.go:
- `grpcStatusToHTTP(err error) int` - converts gRPC status codes to HTTP status codes. If the gRPC error is `codes.Unavailable`, return 503 (service unavailable). Map other codes: NotFound->404, InvalidArgument->400, PermissionDenied->403, Unauthenticated->401, AlreadyExists->409, Internal->500.
- `respondJSON(w http.ResponseWriter, status int, data interface{})` - write JSON response (or delegate to existing `response.JSON` from `internal/server/response` package)
- `respondError(w http.ResponseWriter, status int, message string)` - write error JSON response
- `parseUUID(s string) (uuid.UUID, error)` - parse UUID from URL parameter
- Any other common helpers used across multiple handler methods in http.go (inspect the existing handler methods for shared patterns like pagination parsing, etc.)

Important: Check if `backend/internal/server/response/` package already has JSON/error helpers. If so, import and reuse them in helpers.go rather than duplicating. The gateway package should import from response package, not redefine.
