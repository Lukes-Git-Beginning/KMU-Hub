  <action>
    1. Update `main.tsx` to configure TanStack Query persistence:
       - Import PersistQueryClientProvider and createSyncStoragePersister
       - Configure persister with localStorage and key 'kmuhub-query-cache'
       - Set maxAge to 24 hours (1000 * 60 * 60 * 24)
       - Set gcTime on QueryClient to match (24 hours)
       - Set staleTime to 5 minutes
       - This means: cached data survives 24h, is considered stale after 5min, and gets background-refreshed when online
       - Import onlineManager from @tanstack/react-query and set it up:
         ```typescript
         import { onlineManager } from '@tanstack/react-query';
         onlineManager.setEventListener((setOnline) => {
           const onlineHandler = () => setOnline(true);
           const offlineHandler = () => setOnline(false);
           window.addEventListener('online', onlineHandler);
           window.addEventListener('offline', offlineHandler);
           return () => {
             window.removeEventListener('online', onlineHandler);
             window.removeEventListener('offline', offlineHandler);
           };
         });
         ```
       - This makes TanStack Query automatically pause queries when offline and resume when online

    2. Update `hooks/useOnlineStatus.ts`:
       - Track navigator.onLine state
       - Expose isOnline boolean
       - On transition online -> offline: log warning, disconnect WebSocket gracefully
       - On transition offline -> online: reconnect WebSocket, invalidate all queries (trigger refetch of stale data)
       - Use useEffect for event listeners, clean up on unmount

    3. Create `components/layout/OfflineBanner.tsx`:
       - Persistent banner at top of app when offline
       - Yellow/amber background with WifiOff icon: "Offline -- Daten werden aus dem Cache angezeigt. Aenderungen sind nicht moeglich."
       - Slides down smoothly (transition) when going offline, slides up when online
       - Shown above the Header component (or inside AppShell at the very top)
       - When coming back online: brief green "Wieder verbunden" (Connected) banner that fades after 3 seconds

    4. Update `components/layout/Header.tsx`:
       - Add OfflineBanner above or within the header area
       - Small connection status dot in header: green (online), amber (connecting), red (offline)

    5. Update `api/client.ts` to handle offline state:
       - On request middleware: if !navigator.onLine, throw a specific OfflineError for mutations (POST, PUT, DELETE)
       - Allow GET requests to proceed (they'll be served from TanStack Query cache)
       - This prevents users from triggering mutations that would fail silently

    6. Update `stores/auth.ts`:
       - On initialize: if offline, load user from localStorage cache (not API call)
       - On login: if offline, show error "Anmeldung erfordert eine Internetverbindung"
       - refreshToken: if offline, skip refresh (use cached access token until online)

    7. Update backend CORS for Electron:
       - In `backend/internal/config/config.go`: update default CORS_ALLOWED_ORIGINS to include Electron dev port:
         `default=http://localhost:3000;http://localhost:5173`
       - The existing delimiter is `;` which works
       - Also update `backend/.env.example` to document the Electron dev port

    8. Check and update `backend/cmd/gateway/main.go` CORS middleware if it uses the config origins properly (it should already via cfg.CORSAllowedOrigins, just verify).

    NOTE on localStorage cache size: localStorage has a ~5-10MB limit. For a CRM with hundreds of contacts + deals + messages, this could fill up. Add a try/catch around localStorage.setItem in the persister configuration and log a warning if QuotaExceededError occurs. TanStack Query's persistence handles this gracefully by default (fails silently), but we should log it.
