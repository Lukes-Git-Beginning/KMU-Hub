  <action>
    1. Create `lib/constants.ts`:
       - API_BASE_URL: `import.meta.env.RENDERER_VITE_API_URL || 'http://localhost:8080'`
       - WS_RECONNECT_DELAYS: [3000, 6000, 12000, 24000, 48000, 60000] (exponential backoff with 60s max)
       - MAX_RECONNECT_ATTEMPTS: 10
       - STALE_TIME: 5 * 60 * 1000 (5 min)
       - GC_TIME: 24 * 60 * 60 * 1000 (24h for offline)

    2. Create `api/client.ts`:
       - Import createClient from openapi-fetch and paths type from ./types
       - Create apiClient instance with baseUrl from constants
       - Add request middleware that:
         a) Gets accessToken from auth store (import useAuthStore.getState)
         b) Attaches Authorization: Bearer header if token exists
       - Add response middleware that:
         a) On 401: attempt token refresh via auth store's refreshToken()
         b) If refresh succeeds, retry the original request with new token
         c) If refresh fails, call auth store's logout()
         d) Handle race conditions: use a refreshPromise variable to prevent concurrent refresh attempts
       - Export apiClient

    3. Create `api/websocket.ts` -- WebSocketManager class:
       - Private fields: ws, handlers Map<string, Set<callback>>, reconnectTimer, reconnectAttempt, url, state enum (disconnected/connecting/connected)
       - connect(accessToken): create WebSocket to ws://baseUrl/api/v1/ws?token=accessToken
       - onmessage: parse JSON, look up handlers by msg.type, call each
       - onclose: increment attempt, schedule reconnect with exponential backoff from constants
       - onerror: log error
       - on(type, handler): register handler, return cleanup function
       - send(message): JSON.stringify and send if connected
       - disconnect(): clear timer, close socket, reset state
       - getState(): return current connection state
       - Export singleton instance: `export const wsManager = new WebSocketManager(API_BASE_URL)`

    4. Create `stores/auth.ts` -- Zustand store:
       - State: user (User | null), accessToken (string | null), isAuthenticated (boolean), isLoading (boolean)
       - User type: { id, email, firstName, lastName, role } (match backend User model)
       - initialize(): check window.electronAPI.getStoredTokens(), if found set accessToken + isAuthenticated, fetch user profile via GET /api/v1/users/me (check OpenAPI spec for exact path), set user
       - login(email, password): POST /api/v1/auth/login, store tokens via window.electronAPI.storeTokens(), set state, connect WebSocket
       - logout(): POST /api/v1/auth/logout (if endpoint exists), clear tokens via IPC, disconnect WebSocket, reset state
       - refreshToken(): POST /api/v1/auth/refresh with current refresh token, update stored tokens, return new access token
       - Check actual OpenAPI spec paths for auth endpoints (register, login, refresh, logout, me)

    5. Create `stores/ui.ts` -- Zustand store with persist middleware:
       - State: sidebarCollapsed (boolean), sidebarWidth (number, default 256), locale (string, default 'de'), theme ('light' | 'dark', default 'light')
       - Actions: toggleSidebar, setSidebarWidth, setLocale, setTheme
       - Persist to localStorage with key 'kmuhub-ui'

    6. Create `hooks/useElectronIPC.ts`:
       - useNativeNotification(): returns showNotification(title, body) that calls window.electronAPI.showNativeNotification
       - useWindowControls(): returns { minimize, maximize, close, isMaximized }
       - usePlatform(): returns window.electronAPI.platform

    7. Create `hooks/useOnlineStatus.ts`:
       - Track navigator.onLine state via useState
       - Listen to 'online' and 'offline' window events
       - Return { isOnline } boolean
       - Clean up listeners on unmount

    8. Create `hooks/useWebSocket.ts`:
       - useWebSocket(): connects wsManager when auth store has accessToken, disconnects on logout
       - useWSSubscription(type, handler): subscribes to specific message type, returns cleanup
       - useEffect to manage lifecycle tied to auth state
  </action>
  <verify>

    - websocket.ts has exponential backoff reconnection logic
    - auth store uses window.electronAPI for token persistence (not localStorage)
    - ui store uses zustand persist middleware with localStorage
  </verify>
