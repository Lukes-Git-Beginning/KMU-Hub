**WOPI token service (`backend/internal/document/wopi/token.go`):**

Create `TokenService` that generates and validates purpose-specific WOPI JWTs, SEPARATE from the main application JWT:

```go
type WOPITokenClaims struct {
    jwt.RegisteredClaims
    FileID   string `json:"file_id"`
    UserID   string `json:"user_id"`
    UserName string `json:"user_name"`
    CanWrite bool   `json:"can_write"`
}

type TokenService struct {
    secret []byte
}

func NewTokenService(secret string) *TokenService
func (s *TokenService) Generate(fileID, userID, userName string, canWrite bool) (token string, ttlMs int64, err error)
func (s *TokenService) Validate(tokenString string) (*WOPITokenClaims, error)
```

TTL: 10 hours (per WOPI spec recommendation). Use HS256 signing. The WOPI secret is a SEPARATE env var `WOPI_JWT_SECRET`, NOT the same as the app JWT secret.

**WOPI lock service (`backend/internal/document/wopi/lock.go`):**

Create `LockService` that manages file locks in PostgreSQL with 30-minute auto-expiry:

```go
type LockService struct {
    pool *pgxpool.Pool
}

func NewLockService(pool *pgxpool.Pool) *LockService
func (s *LockService) Lock(ctx context.Context, fileID, lockID, userID string) error
func (s *LockService) Unlock(ctx context.Context, fileID, lockID string) error
func (s *LockService) RefreshLock(ctx context.Context, fileID, lockID string) error
func (s *LockService) GetLock(ctx context.Context, fileID string) (lockID string, err error)
func (s *LockService) CleanExpired(ctx context.Context) (int, error)
```

Lock: INSERT ON CONFLICT UPDATE (if same lockID or expired, acquire; if different lockID and not expired, return ErrLockConflict with current lockID in error). Unlock: DELETE WHERE fileID AND lockID match. RefreshLock: UPDATE expires_at WHERE fileID AND lockID match. GetLock: SELECT lock_id WHERE not expired. CleanExpired: DELETE WHERE expires_at < NOW().

Define errors: ErrLockConflict (includes CurrentLockID field), ErrLockNotFound.

**WOPI handler (`backend/internal/document/wopi/handler.go`):**

Create `Handler` that implements WOPI REST endpoints per the OnlyOffice WOPI spec:

```go
type Handler struct {
    tokenService *TokenService
    lockService  *LockService
    fileService  FileServiceInterface  // minimal interface to avoid circular imports
    fileStore    chatfile.FileStore
}
```

Define `FileServiceInterface` with just the methods WOPI needs: GetByID, GetDownloadURL, CreateVersion.

Endpoint handlers (called from route_wopi.go):
- `CheckFileInfo(w, r)` — GET /wopi/files/{file_id}: Validate access_token query param via tokenService.Validate. Get file metadata. Return JSON with: BaseFileName, Size, Version, OwnerId, UserId, UserFriendlyName, UserCanWrite, UserCanRename, SupportsLocks, SupportsUpdate, SupportsRename, SHA256 (if available). Content-Type: application/json.
- `GetFile(w, r)` — GET /wopi/files/{file_id}/contents: Validate token. Download from MinIO. Stream to response with Content-Type from file metadata. Set X-WOPI-ItemVersion header.
- `PutFile(w, r)` — POST /wopi/files/{file_id}/contents: Validate token (must have CanWrite). Verify lock (if locked, lock must match X-WOPI-Lock header). Read body, upload to MinIO as new version, create version record (auto-version on save). Return 200.
- `HandleLockOperation(w, r)` — POST /wopi/files/{file_id}: Read X-WOPI-Override header. Dispatch to Lock, Unlock, RefreshLock, PutRelativeFile based on override value. For Lock: call lockService.Lock with X-WOPI-Lock header value. If conflict, return 409 with X-WOPI-Lock set to current lock. For Unlock: call lockService.Unlock. For RefreshLock: call lockService.RefreshLock. Return 200 on success.

All WOPI responses must include X-WOPI-ServerVersion header.
