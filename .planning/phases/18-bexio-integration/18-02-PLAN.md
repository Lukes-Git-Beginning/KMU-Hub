    ## Contact Sync Engine

    Create `backend/internal/biz/bexio/contact_sync.go`:

    **`ContactSyncer`** struct with client, repo, field mapper, CRM contact service reference.

    **`SyncContacts(ctx, configID, tenantID) (*SyncResult, error)`:**
    1. Create sync log entry (status: running)
    2. Load field mappings for entity_type='contact' from repo
    3. Refresh lookup cache
    4. Get last sync timestamp from sync config
    5. **Inbound (Bexio -> KMU Hub):**
       - Fetch contacts from Bexio with `updated_since` filter (nil for full sync)
       - For each Bexio contact:
         - Check entity mapping: existing or new?
         - If existing: compare `updated_at` timestamps (last-write-wins)
         - If Bexio newer: map to KMU Hub format, update in CRM service
         - If new: map to KMU Hub format, create in CRM service, create entity mapping
       - Track items_created, items_updated, items_failed
    6. **Outbound (KMU Hub -> Bexio):**
       - Query CRM contacts modified since last sync
       - For each modified contact:
         - Check entity mapping: existing or new?
         - If existing: compare timestamps (last-write-wins)
         - If KMU Hub newer: map to Bexio format, update in Bexio API
         - If new: map to Bexio format, create in Bexio API, create entity mapping
    7. Update sync config last_contact_sync_at
    8. Update sync log (status: completed/partial/failed)
    9. Return SyncResult with counts

    **`SyncResult`** struct: ItemsProcessed, ItemsCreated, ItemsUpdated, ItemsFailed, Errors []string

    **Conflict Resolution (Last-Write-Wins):**
    - Compare `bexio_updated_at` from mapping vs current Bexio `updated_at`
    - Compare `kmuhub_updated_at` from mapping vs current KMU Hub `updated_at`
    - The most recently modified version wins
    - Update mapping timestamps after sync

    ## Invoice Push

    Create `backend/internal/biz/bexio/invoice_push.go`:

    **`InvoicePusher`** struct with client, repo, field mapper, invoice service reference.

    **`PushInvoice(ctx, configID, tenantID, invoiceID uuid.UUID) error`:**
    1. Load invoice from KMU Hub invoice service
    2. Load contact entity mapping (invoice must have a synced contact)
    3. Load field mappings for entity_type='invoice'
    4. Map invoice to Bexio format
    5. Check entity mapping: update existing or create new in Bexio
    6. Store/update entity mapping with Bexio invoice ID
    7. Log sync result

    **Trigger:** Called when invoice status changes to "sent" (via event listener in service).

    ## Quote Push

    Create `backend/internal/biz/bexio/quote_push.go`:

    **`QuotePusher`** struct — mirrors InvoicePusher pattern.

    **`PushQuote(ctx, configID, tenantID, quoteID uuid.UUID) error`:**
    1. Load quote from KMU Hub quote service
    2. Load contact entity mapping
    3. Load field mappings for entity_type='quote'
    4. Map quote to Bexio format (KB offer)
    5. Create or update in Bexio
    6. Store/update entity mapping
    7. Log sync result

    **Trigger:** Called on quote create/update.

    ## Payment Polling

    Create `backend/internal/biz/bexio/payment_poll.go`:

    **`PaymentPoller`** struct with client, repo, invoice service reference.

    **`PollPayments(ctx, configID, tenantID) (*SyncResult, error)`:**
    1. Create sync log entry
    2. List all invoice entity mappings for this config
    3. For each mapped invoice:
       - Fetch payment status from Bexio API
       - Compare with current KMU Hub payment status
       - If Bexio shows paid but KMU Hub doesn't: call invoice service MarkPaid
       - If Bexio shows partial payment: update payment amount in KMU Hub
    4. Update sync config last_payment_poll_at
    5. Update sync log
    6. Return SyncResult

    **Optimization:** Only poll invoices with status != "paid" in KMU Hub (skip already settled).

    ## Background Scheduler

    Create `backend/internal/biz/bexio/scheduler.go`:

    **`Scheduler`** struct:
    - Map of tenant schedulers (goroutines per active tenant)
    - Service reference for calling sync methods
    - Repository for loading sync configs

    **`StartScheduler(ctx context.Context) error`:**
    1. Load all active bexio integration configs from DB
    2. For each active config, start tenant scheduler goroutine

    **`startTenantScheduler(ctx, configID, tenantID string)`** goroutine:
    1. Load sync config for intervals
    2. Create two tickers: contact sync (default 15 min) and payment poll (default 5 min)
    3. Loop:
       - On contact ticker: call `service.SyncContacts(ctx, tenantID)`
       - On payment ticker: call `service.PollPayments(ctx, tenantID)`
       - On ctx.Done(): stop tickers, return
    4. Recover from panics with `slog.Error` logging

    **`StopTenantScheduler(tenantID string)`** — cancels context for a specific tenant's goroutine.

    **`StopAll()`** — graceful shutdown of all tenant schedulers.

    **`AddTenant(ctx, configID, tenantID string) error`** — starts scheduler for newly connected tenant.

    **`RemoveTenant(tenantID string)`** — stops scheduler for disconnected tenant.

    Use `sync.Map` for thread-safe tenant goroutine management. Log all scheduler start/stop events via `slog`.
