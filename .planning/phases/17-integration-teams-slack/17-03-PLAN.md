    **useIntegration.ts** -- TanStack Query hooks following existing project patterns (see api/hooks/ directory):
    - Query key prefix: `['integration', ...]`
    - `useIntegrationConfigs()` -- GET /api/v1/integrations/configs, returns IntegrationConfig[]
    - `useIntegrationConfig(platform: Platform)` -- GET /api/v1/integrations/configs/{platform}
    - `useCreateIntegrationConfig()` -- POST mutation, invalidates ['integration', 'configs']
    - `useUpdateIntegrationConfig(platform: Platform)` -- PUT mutation, invalidates ['integration', 'configs']
    - `useDeleteIntegrationConfig(platform: Platform)` -- DELETE mutation, invalidates ['integration', 'configs']
    - `useTestIntegrationConfig(platform: Platform)` -- POST mutation (no cache invalidation, just fire-and-forget)
    - `useChannelMappings(platform: Platform)` -- GET /api/v1/integrations/configs/{platform}/mappings
    - `useCreateChannelMapping(platform: Platform)` -- POST mutation, invalidates ['integration', 'mappings', platform]
    - `useUpdateChannelMapping()` -- PUT mutation, invalidates ['integration', 'mappings']
    - `useDeleteChannelMapping()` -- DELETE mutation, invalidates ['integration', 'mappings']
    - `useAccountLinkStatus(platform: Platform)` -- GET /api/v1/integrations/link/{platform}/status
    - `useLinkAccount()` -- POST mutation, invalidates ['integration', 'link']
    - `useUnlinkAccount(platform: Platform)` -- DELETE mutation, invalidates ['integration', 'link']
    - Use existing `request` helper from api client (same pattern as other hook files)
    - All hooks return standard TanStack Query result shape
    - Mutations use optimistic updates where applicable (enable/disable toggle for configs and mappings)
