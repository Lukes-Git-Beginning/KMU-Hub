## Architektur

### Verzeichnisstruktur
```
desktop/src/renderer/src/i18n/
  i18n.ts              — Initialisierung (44 Zeilen, 4 statische Imports)
  i18next.d.ts         — Strict Type Declarations (resources → de.json)
  messages/
    de.json            — 7.221 Keys (Deutsch, Source of Truth)
    en.json            — 7.221 Keys (Englisch)
    fr.json            — 7.221 Keys (Franzoesisch)
    it.json            — 7.221 Keys (Italienisch)
```

### Initialisierung (i18n.ts)
- `keySeparator: false` — **kritisch**, flat dot-notation Keys
- `nsSeparator: false` — kein Namespace-Splitting
- `fallbackLng: 'de'` — Deutsch als Fallback
- ICU-Plugin fuer `{count, plural, ...}` Syntax
- 4 statische JSON-Imports (de/en/fr/it), kein Lazy Loading
- Kein Backend/HTTP-Loader (Electron — alle Resources lokal)

### Type Safety (i18next.d.ts)
```typescript
import type de from '@/i18n/messages/de.json'
declare module 'i18next' {
  interface CustomTypeOptions {
    defaultNS: 'translation'
    returnNull: false
    resources: { translation: typeof de }
  }
}
```
→ `t()` Calls werden zur Compile-Zeit gegen de.json validiert.

## Verwendungsmuster

### In React-Komponenten
```tsx
import { useTranslation } from 'react-i18next'

function MyComponent() {
  const { t } = useTranslation()
  return <h1>{t('crm.contacts.title')}</h1>
}
```

### In .ts Dateien (ausserhalb React)
```typescript
import i18next from 'i18next'
const label = i18next.t('common.save')
```

### Dynamische Keys (haeufig verwendet)
```tsx
// Template Literals — Keys muessen in JSON existieren
t(`security.admin.tab.${tab.key}`)
t(`header.connectionStatus.${status}.label`)
t(`kalender.form.recurrence.${opt}`)
```

### Datum/Zahlen-Formatierung
- `useFormatDate()` / `useFormatNumber()` Hooks
- Datei: `hooks/useFormatters.ts`
- Nutzt `Intl.DateTimeFormat` / `Intl.NumberFormat` mit aktuellem Locale

### LanguageSwitcher
- Datei: `components/header/LanguageSwitcher.tsx`
- 4 Locales: de, en, fr, it
- Nutzt `useLocaleStore` (Zustand) + `i18n.changeLanguage()`

## Schluessel-Konventionen

1. **Format:** `modul.bereich.label` (z.B. `crm.contacts.title`, `dashboard.widgets.revenue`)
2. **Marken-Namen hardcoded:** Cosmi, Zentria, Bexio, DATEV, Lexware, FinAPI — NIE in `t()` wrappen
3. **Technische Strings hardcoded:** CSS-Klassen, URLs, IDs, Enum-Values
4. **ICU-Format:** `{count, plural, one {# Eintrag} other {# Eintraege}}`

## Lessons Learned
- Agents verbrauchen bis zu 250k Tokens bei >10 Dateien — max 5-7 Dateien pro Agent
- JSON-Extraktion separat von Instrumentierung — sauberer und verifizierbar
- `keySeparator: false` muss explizit gesetzt sein, sonst Dot-Notation als Nesting interpretiert
- Uebersetzungen in 3 Chunks × 3 Agents parallel — effizient fuer grosse Key-Sets
- Merge-Script (Node) statt manuell — schnell und fehlerfrei
- Mock-Daten in Stores nicht instrumentieren — werden durch Backend-Daten ersetzt
