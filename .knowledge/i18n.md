## Architektur

### Verzeichnisstruktur
```

  i18next.d.ts         — Type Declarations (aktuell permissiv)
  locales/
    de.json            — Basis-Bundle (Deutsch)
    en.json            — Englisch (Shell, noch leer)
    fr.json            — Franzoesisch (Shell, noch leer)
    it.json            — Italienisch (Shell, noch leer)
  additions/
    dashboard.json     — 187 Keys

    work.json          — 323 Keys
    ...                — 41 Dateien total
```

### Initialisierung (i18n.ts)
- `keySeparator: false` — **kritisch**, flat dot-notation Keys
- `nsSeparator: false` — kein Namespace-Splitting
- `fallbackLng: 'de'` — Deutsch als Fallback
- ICU-Plugin fuer `{count, plural, ...}` Syntax
- Statische Imports aller 41 Additions-JSONs (kein Lazy Loading)
- Kein Backend/HTTP-Loader (Electron — alle Resources lokal)
- `mergedDE` Spread-Pattern:

```typescript
const mergedDE = {
  ...deBase,
  ...dashboardAdditions,
  ...crmAdditions,
  ...workAdditions,
  // ... 41 Additions total
}
```

## Verwendungsmuster

### In React-Komponenten
```tsx
import { useTranslation } from 'react-i18next'

function MyComponent() {
  const { t } = useTranslation()
  return <h1>{t('crm.contacts.title')}</h1>
}
```

### In .ts Dateien (ausserhalb React)
```typescript
import i18n from '../i18n/i18n'
const label = i18n.t('common.save')
```

### Datum/Zahlen-Formatierung
- `useFormatDate()` / `useFormatNumber()` Hooks
- Datei: `hooks/useFormatters.ts`
- Nutzt `Intl.DateTimeFormat` / `Intl.NumberFormat` mit aktuellem Locale

### LanguageSwitcher
- Datei: `components/header/LanguageSwitcher.tsx`
- 4 Locales: de, en, fr, it
- Nutzt `useLocaleStore` (Zustand) + `i18n.changeLanguage()`

## Schluessel-Konventionen

1. **Format:** `modul.bereich.label` (z.B. `crm.contacts.title`, `dashboard.widgets.revenue`)
2. **Scope:** Keys pro Modul in eigenem additions/*.json
3. **Komponenten-Keys:** `components.header.clock`, `components.shared.confirm`
4. **Marken-Namen hardcoded:** Cosmi, Zentria, Bexio, DATEV, Lexware, FinAPI — NIE in `t()` wrappen
5. **Technische Strings hardcoded:** CSS-Klassen, URLs, IDs, Enum-Values
6. **ICU-Format:** `{count, plural, one {# Eintrag} other {# Eintraege}}` (nicht react-intl's `=1` Notation)

## Lessons Learned
- Agents verbrauchen bis zu 250k Tokens bei >10 Dateien — max 5-7 Dateien pro Agent
- JSON-Extraktion separat von Instrumentierung — sauberer und verifizierbar
- `keySeparator: false` muss explizit gesetzt sein, sonst Dot-Notation als Nesting interpretiert
- Paired Agents besser in separate JSONs schreiben lassen, danach mergen
- Einige Module waren bereits instrumentiert aber hatten keine JSONs — Extraktion-only Agents funktionieren gut
